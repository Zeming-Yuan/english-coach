# ADR-0004：内容修订身份与 V3 完整备份

- 状态：已采纳
- 日期：2026-10-31
- 票据：EL-01（Expand：编辑词卡后仍能完整备份与恢复内容修订）

## 背景

V2 完整备份（ADR-0003）只包含当前业务行与其相互引用。学习证据需要区分“哪些结果
是针对当前内容产生的”：用户修改词形、释义或例句后，旧作答不应继续证明新内容。
同时，后续票据会引入接触记录、课程进度、练习会话等新集合；如果继续把集合硬编码进
V2 协议，新增记录会先被允许丢失，再等最终集成票补救。

## 决策

1. **加法引入内容修订。** 新增 `content_revisions` 表：
   `id`、`resource_kind ∈ {card, lesson, story}`、`resource_id`、`identity`（UUID
   字符串）、`version ≥ 1`，唯一约束 `(resource_kind, resource_id)`。现有实体在
   迁移中补齐当前身份，不生成旧作答或推断历史。
2. **修订规则。** 词卡的 `word`、`meaning`、`example`、`example_cn`、`contexts`，
   课程的 `title`、`content`，故事的 `title`、`content`、`title_cn`、`content_cn`
   的语义变化使 `version + 1`；字符串按折叠空白比较，因此仅排版差异不增加版本。音标、
   讲解与记忆法不改变修订。`identity` 表示实体身份，编辑时保持不变；`version`
   表示当前内容，编辑实质变化时递增。`GET/PUT /api/cards/{id}` 增加
   `content_revision: {identity, version}`，编辑与修订在同一 `BEGIN IMMEDIATE`
   事务中提交；重复保存相同内容不重复递增。
3. **V3 是当前完整备份格式。** 顶层保留 V2 核心集合，并增加
   `features: list[str]` 与 `extensions: dict[str, list[dict]]`。每个扩展集合
   必须在 `app/schemas/backup_v3.py` 通过 `register_extension(name, schema,
   parents, remap, model=...)` 显式登记 schema、父引用、ID 重映射与持久模型；
   登记顺序即导出顺序，导出、校验、ID 映射与恢复删除拓扑共用同一份登记表（核心
   集合按固定依赖序，扩展按登记序插入、逆序删除）。重复登记或未绑定模型的扩展
   拒绝；标记为 complete 的扩展必须为每个父实体包含一行，声明了 `content_revisions`
   却漏行的 V3 在修复前拒绝。读取修订是纯读：创建、迁移与恢复负责初始化身份，
   缺失身份视为数据异常，不在 GET 中写入；写入事务仍可为缺失实体补齐。
4. **特性与集合必须一致。** `features` 与 `extensions` 的键集合必须相同；未知
   功能明确拒绝恢复，旧应用不会静默丢弃后期版本的数据。较早的 V3 可以缺少后来
   登记的集合，预览会明确说明将为空。
5. **旧格式保持可读。** V2 继续使用原严格协议；V1 仍按部分恢复处理。全量替换
   V2/V1 或缺少某扩展的早期 V3 时，预览明确列出缺失集合及替换影响；执行前保存
   当前数据的 V3 安全副本，整个替换仍在单一事务内完成。V2/V1 恢复的词卡、课程
   和故事会获得新的修订身份，旧身份不会冒充新内容。
6. **恢复保留身份。** V3 恢复时 `content_revisions.identity` 随实体保留，仅
   按资源类型重映射 `resource_id`；恢复后继续编辑从原版本递增。恢复前启动的
   后台 AI 任务同时校验卡片内容与修订身份/版本，过期结果不能写入恢复后的实体。
7. **新增集合当票登记。** EL-04 在登记表中加入 `learning_contacts`：父引用
   `cards`、恢复时重映射 `card_id`、校验提交标识与修订身份 UUID、拒绝重复
   提交标识；该集合随 V3 导出/恢复，旧 V2 或早期 V3 缺少时保持未知。
   EL-08 再登记 `practice_sessions` / `practice_items`，题目引用冻结修订与真实学习事件。
   后续票据引入新的持久集合时，必须在同一票登记导出、
   校验、引用映射与恢复，不把数据保护推迟到最终集成票。EL-20 只负责把登记与
   映射 owner 收口到 `app/services/backup_v3_registry.py` 并保留兼容导入。

## 回退方式

隐藏词卡详情的 `revision-panel` 或新版编辑入口即可完成界面回退；`content_revisions`
表、V3 导出/恢复与 V1/V2 兼容读取继续保留，已产生的新学习不受影响。回退应用时
不得删除新列、恢复旧快照或用旧库覆盖已升级实例。功能回退只撤展示与入口，事务
回滚由单一写事务保证，两者分别验收。

## 结果

- V3 可表达并恢复当前阶段全部学习内容与修订身份；未知功能、非法引用、重复身份、
  重复资源修订与保存失败均在写入前拒绝或整体回滚。
- 旧 V2/V1 文件继续可用，但其预览会明确暴露缺失的新集合与替换范围。
- 后续票据必须同步扩展 V3 登记表；未登记模型的扩展会使导出显式失败，而不是
  静默漏数据。
- 回退应用时保留 `content_revisions` 与 V3 适配；不得删除新列或恢复旧快照来覆盖
  已产生的新学习。

## 补充：课程/故事修订字段（EL-06）

- 课程（lesson）的 `title`、`content` 与故事（story）的 `title`、`content`、
  `title_cn`、`content_cn` 属于语义内容；实质变化推进对应修订。故事自动补翻接受时
  推进修订；晚到翻译先校验 identity+version，不一致则丢弃，避免覆盖编辑或恢复后的实体。
- 本票只增加读取端的修订与可见目标载荷，不新增持久集合；`content_revisions` 中
  lesson/story 的导出、校验、映射与恢复沿用既有 V3 登记。

## 补充：主动时长扩展（EL-18）

- 登记 `practice_durations`：整数行 ID、sample UUID、真实作答 submission UUID、
  review/new/reinforcement 类别、原始主动毫秒、`active-v1` 规则身份与服务端 UTC
  保存时间。两个 UUID 各自唯一，数值为非负安全整数；估算时按 ADR-0002 限幅。
- 父集合为 `learning_events`，以保留的 submission UUID 关联，恢复不按词形猜测。
  校验拒绝孤立提交、跳过/未知旧作答、非单词目标、类别与真实事件不符、重复身份、
  非法数值及未知规则。恢复映射词卡/事件后保留该 UUID 关联和样本保存次序。
- 新增集合当票纳入导出、校验、恢复拓扑和预览替换影响。较早 V3/V2 缺失时明确说明
  时长为空、预览使用默认值；V1 部分恢复保留现有记录，没有记录时继续默认。
  全量替换前的安全副本包含时长，失败整体回滚；编辑后的已确认时长可以幂等回放。
- 升级仅追加新表，沿 `el16_feedback_epoch` 单一已交付头升级，旧事件/排期保持原样。
  回退保留表与读取适配，通过功能开关停止个人估算，不执行破坏性 downgrade。
