# ADR-0001：当前记忆状态与只追加学习事件

- 状态：已采纳
- 日期：2026-10-30
- 票据：EC-03（Expand）、EC-04（显式评分保存确认）

## 背景

原实现把一次复习直接覆盖写回 `reviews` 的最新一行。同一天内多次真实评分会互相覆盖，
跨天历史和统计无法还原；同时旧库可能存在同一张卡的多行 `reviews`，无法区分哪一行
代表当前状态。可靠统计、每日流程与备份恢复都需要「当前状态 + 完整历史」的稳定契约。

## 决策

1. **当前记忆状态继续复用 `reviews`。** 不新建需要全局双写的状态表。EC-03 的读取统一由
   `app.services.learning.get_memory_state` 完成：同卡多行时按最新有效 `last_review`、
   再按记录顺序（`id`）选择。EC-15 已通过迁移收紧单卡唯一约束（见下文）。
2. **每次被接受的学习提交追加一行 `review_events`。** 事件保存提交标识、来源、题型、
   阶段、UTC 接收时间、学习时区与学习日、答案、可空客观正误、是否跳过、提示、自评分、
   实际采用的 FSRS 评分、是否排期、排期前后摘要、指纹、规范化命令与缓存响应。
   `submission_id` 由数据库唯一约束兜底并发重试。
3. **升级前的旧行保存为 `review_baselines`。** 每行保留原始 JSON 快照、源行 ID、
   最后活动与累计次数；`selected` 标出当前状态来源行。基线不是作答事件，不按
   `review_count` 伪造历史日期或正确率；界面需要明确标注历史不完整。
4. **事务所有权在写模块。** `run_write` 在干净请求会话中执行 `BEGIN IMMEDIATE`，
   幂等检查、事件追加、FSRS 更新与错词变化同一事务提交；异常整体回滚。路由不查询
   数据库后再进入写模块，也不自行 commit。
5. **幂等与冲突。** 同 `submission_id` 同内容回放返回首次保存的响应，不再次排期；
   同标识不同内容返回 409；没有提交标识的旧调用每次生成随机标识，不承诺跨请求幂等。
6. **未知旧数据保持未知。** 没有来源/题型的旧请求记为 `source=legacy`，不进入
   客观正确率或自适应样本；`history_incomplete` 由迁移基线或未分类事件显式驱动。
7. **后台 AI 在提交之后。** 毕业句卡的 AI 升级只在事务提交后启动，沿用请求上下文中的
   LLM 绑定；AI 结果不影响本次学习提交是否成功。
8. **显式自评分先确认后推进（EC-04）。** 每个评分入口持有单个待确认提交，浏览器用
   稳定 `submission_id` 构造 pending；只有服务端返回 `committed=true` 才推进、关闭
   面板或增加完成数。失败保留当前题、评分与提交标识，可重试同一请求或明确放弃；
   AI 升级、TTS 或页面动画不决定保存是否完成。
9. **刷新恢复不做离线重放。** pending 在发送前写入本地存储；刷新后首页列出未确认
   提交，由用户选择继续确认或放弃，核实成功后才重新加载队列。本地存储不可写时
   仅保留内存 pending，并提示「本次操作尚未确认保存；刷新后可能需要重新核对」；
   不提供后台队列、自动重放或换用新标识冒充成功。卡片已删除返回 404，允许明确放弃。

## 后果

- 词卡详情可以展示真实评分轨迹，同时保留原有 `review_history` 与当前排期字段给旧消费者。
- 统计、自适应与备份恢复可以在后续票据中只依赖事件与基线，不再读取被覆盖的当前行。
- 旧库升级会为每张卡保留全部旧行快照，数据库体积随旧行数增加；这是可追溯性的代价。
- 旧历史只能展示最后可知活动与累计次数，界面必须诚实标注「历史不完整」。

## 输入题、提示与排期映射

- `POST /api/typing/check` 是输入题的薄适配器，经 `submit_attempt` 一次事务完成判分、
  事件、错词与必要排期；不再由页面先判分再另发 `/api/reviews`。
- 独立输入（`kind=typed`、`source` 非 `legacy`、`assistance` 为空）答对采用 FSRS 3、
  答错采用 1；空答案按答错处理，只有 `skipped=true` 才记录 `correct=null`。
- 任一提示（首字母、长度、逐字反馈、答案朗读、答案可见）或 `source=legacy` 的输入
  只保存客观结果，不更新 FSRS；跳过同样不更新，也不增加错词权重。
- 同一 `submission_id` 的回放返回原事件，不重复判分、排期或改错词；同标识不同答案 409。

## 界面与兼容字段

- 词卡详情新增 `memory_state`、`learning_events`、`history_incomplete`；
  原 `review_history`、`review_count`、`next_due` 等字段保留给旧消费者。
- 学习记录只遍历真实事件；迁移基线不进入事件数组，只用于「最后可知活动」与
  「历史不完整」提示。未分类旧事件显示为“未分类”，不把自评分画成客观答错。
- 界面能显示轨迹不代表旧数据已补全；历史不完整提示必须由 `history_incomplete`
  显式条件驱动，不能在新库上无条件出现。

## EC-06 补充：识别题不排期与可验证题目上下文

1. **识别练习只记事件、不更新 FSRS。** 看中文选词、听力四选一与相关词选择以
   `correct` 记录客观结果，`fsrs_rating` 为空、`scheduled=false`，不写 `reviews`；
   跳过记录 `correct=null`。客户端另传的自评分或下标不能覆盖该策略。
2. **题目上下文由服务端签名。** `app.services.questions.issue_question` 用应用启动
   生成的密钥对 `card_id/kind/options/expected/expires_at` 做 HMAC；提交只接受选项
   文本，服务端按验签后的 `expected` 判分。默认有效期 24 小时，密钥不进入备份。
3. **失效与篡改可区分。** 过期或服务重启（密钥变化）返回 409，提示重新加载题目；
   签名损坏、上下文与提交不匹配或答案不在选项中返回 422。缺失卡片返回 404。
   旧版只传 `selected_index/correct_index` 的调用无法验证题目上下文，不再受理。
4. **回放优先于过期。** 同一 `submission_id` 若与原事件保存的 token 相同，使用
   `command_json` 中已验业务上下文比对指纹并返回缓存结果，不因 24 小时过期而失败；
   换 token 必须重新验签。同标识不同内容仍返回 409。
5. **批量原子。** `POST /api/quiz/score` 在单次 `run_write` 中先全量校验（卡片、
   上下文、答案、幂等冲突），再逐项追加事件；任一项失败整批回滚。每项使用独立
   `submission_id`，响应保留 `total/correct/score/details`。

## 回退

撤回事件展示或新入口适配时，保留 `review_events`、`review_baselines` 与已追加事件，
不删除新增数据；旧读取路径继续使用 `reviews` 的当前状态。不得用旧快照覆盖新进度。
关闭选择入口时保留签名题目协议与识别事件，不退回信任客户端下标的判分方式，
也不把已记录的识别结果重新转换成 FSRS 复习。

## EC-15：当前状态契约收口

迁移 `b1c2d3e4f503` 接在 `ec12_card_identity` 后，先用反射/Core 预检旧状态；无法安全解释的时间、计数或评分使升级停止。重复卡的尚未存档快照以 `contract_archive` 基线完整保留，再按有效 `last_review`、`id` 选择一行，加 `uq_reviews_current_card` 唯一索引。已有同指纹基线不重复归档，归档不生成事件、不增加可靠统计。迁移只增索引，不重建词卡表，不改变 `sqlite_sequence`。

`get_memory_state` 读取唯一当前行；列表和每日队列的 `select_current_review` 仍有消费者，保留兼容接口。物理 Review 字段、事件、基线和公共 URL 保留。详情的 `review_history` 合并物理当前行与原始基线，完全相同的快照只显示一次；真实 `learning_events` 独立展示。降级只撤唯一索引，保留归档、事件、已归并状态与词卡分配器；再次升级不会重复归档。撤约束不自动复活旧重复状态或覆盖后续学习。
