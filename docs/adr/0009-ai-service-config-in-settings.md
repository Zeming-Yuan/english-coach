# ADR-0009：设置页管理 AI 服务配置

- 状态：已采纳
- 日期：2026-11-04
- 票据：无（用户直接需求）

## 背景

AI 服务的地址、密钥和模型原先只能改 `.env`。配置错误时界面只表现为“暂无释义”或生成失败，用户看不到 401/404 的原因；本地单用户应用也不该要求用户理解环境变量优先级。实际发生过两次：密钥失效返回 401、误填 Anthropic 协议地址导致 404。

## 决策

- 设置页新增「AI 服务」：服务地址、模型、API Key，保存前可「测试连接」。
- 新增 `/api/ai-config`：GET 返回 `base_url`、`model`、`has_key`，永不返回密钥；PUT 保存并热生效；POST `/test` 用候选配置做一次最小请求，只试不存。
- 配置写入本机 `data/llm_config.json`（原子替换），启动时加载，优先级高于 `.env`。保存后替换 `app.state.llm_client`，后续请求立即使用新配置。
- 密钥留空表示沿用已保存值；换服务地址时必须重新输入密钥（保存与测试连接都拒绝），避免把已存密钥发往新地址。
- 校验：地址必须以 `http://` 或 `https://` 开头，模型不能为空。
- 文件位于 `data/`（已 gitignore），不随数据库备份导出，避免密钥外流。

## 后果

- 密钥以明文保存在本机文件，信任边界与 `.env` 相同；接口不回显、不写日志。
- 界面配置覆盖 `.env`；删除 `data/llm_config.json` 可回到环境变量配置，UI 不提供“清除”入口。
- 仅支持 OpenAI 兼容协议；「测试连接」能直接暴露地址错误、鉴权失败和模型名不存在。
- 测试进程通过 `LLM_CONFIG_PATH` 指向临时路径，绝不读取开发者本机配置。
- 热生效只覆盖当前进程；本应用按本地单进程运行，多 worker 部署需重启其他进程。

## 补充：配置管理的本机边界（2026-11-05）

- `PUT /api/ai-config` 与 `POST /api/ai-config/test` 仅接受 TCP 对端为
  loopback IP 的本机直连请求；无对端、非 IP 对端和远端请求拒绝为 403。
- 带 `Forwarded`、`X-Forwarded-*` 或 `X-Real-IP` 来源标记的请求也拒绝，
  不信任客户端声明的本机地址。反代部署必须隔离这两个管理路由；隐藏来源且不带
  任何转发标记的本机反代无法由应用可靠辨认，不属于此边界保护范围。
- 保留自定义 HTTP/HTTPS 地址及本机、私网 LLM 支持；不以 DNS 预检查充当安全边界。
  loopback 判断使用服务器收到的对端地址，不采信转发头。
- 测试连接失败仅返回固定可读建议；上游存在合法 HTTP 状态码时可返回该状态码，
  不回显异常正文、密钥、内部地址或上游响应正文。
