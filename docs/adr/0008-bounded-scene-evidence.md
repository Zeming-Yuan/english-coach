# ADR-0008：限定三轮场景与独立应用证据

- 状态：已采纳
- 日期：2026-11-02
- 票据：EL-14 / #50

场景复用持久练习轮次，但任务不是词卡评分。买饮品固定请求水、表达一杯、确认并致谢三个任务；随应用分发经人工核对的中文角色模板、完整句式、槽位和拒绝集合。完整匹配才认可，显式不满足才拒绝，其他表达未判定；空答案继续输入，显式跳过单列。规则版本、内容修订及摘要随轮次冻结，不调用 AI 判分。

`scene_attempts` 只追加真实提交，题目引用唯一首答 UUID；新标识再次作答保存为辅助再练，不覆盖首答。三题首答全部认可且无帮助才独立通过，其他三题已处理仅表示流程完成。请求提示或标准表达先保存只增不减的帮助，再返回内容；准备页仅展示中文释义、准备状态与缺词数量，避免提前回显可直接作答的词形；标准表达实际展示及实际开始朗读通过既有接触接口分别记录 source=scene 的可见/音频接触，失败保留原接触身份供确认，语音失败不撤销保存。

创建、原标识回放、作答及完成生命周期均在既有 `run_write` 的 BEGIN IMMEDIATE 内确认。缓存响应先于规则/词卡失效检查，同标识异内容 409；提交标识跨词卡与场景使用同样冲突。无效输入 422，缺失目标 404，修订或规则变化 409。多任务共享的任一目标变化后整轮停止新作答，保留原答案和历史读取；不悄悄换目标。

应用维度只读取当前词卡身份/修订上的任务首答。成功需三题独立通过，且该任务明确映射到此目标，答案不照抄已存例句、存量教学例句也没有命中同一任务模板。保存词卡例句、课程例句/对话的教学快照和限定情境 `drinks:water-order` 作为依据；这只验证固定任务，不推断其他场景、口语或全部词汇能力。未知、跳过、帮助、再练不生成独立成功；独立明确失败只降低相应目标的应用维度，回忆与保持不改写。超过 30 天显示历史应用证据。

场景记录不生成 ReviewEvent，不调用 FSRS，不计入词卡完成量、客观输入正确率或连续学习日。PracticeItem 的词卡关联为场景任务留空；目标映射引用稳定业务身份与修订，无本地整数 ID。删除词卡不会级联删掉场景历史。

V3 当票登记全部场景数据，强类型校验用途、三个任务、规则快照、目标映射、首答/再练引用、业务指纹和缓存结果。恢复保留 UUID 与规则身份，词卡整数 ID 沿既有恢复分配器重映射，不重新判分或排期。早期 V3/V2/V1 缺少场景记录时明确标注未记录，不补造能力；已删除目标作为历史身份保留。今后新增规则版本必须保留旧规则材料及兼容校验，不能覆盖旧文件后丢弃恢复能力。

功能回退使用 `SCENES_ENABLED=false` 并重启：关闭新场景启动，保留原创建确认、已存轮次读取/作答、V3 导出恢复，应用摘要显示历史说明。恢复 true 可逆开启。迁移只扩展并保留所有数据；降级拒绝删除新表，不用旧快照覆盖新学习。

## EL-15：自我介绍与虚构问路

2026-11-03 扩展为三类场景，继续使用同一 Session/SceneAttempt、首答、帮助与事务契约。自我介绍固定 name/origin/preference，姓名与来自地点只填槽位；喜好限定喜欢茶，目标为 tea。问路固定 destination/direction/confirmation，仅在虚构广场到车站、路口左转的情境中判定，分别映射 station/left/thank。不将此结果外推为真实导航、专名拼写、口语或综合英语能力。

准备状态、角色称谓、继续/新开轮次及应用证据都按场景选择；V3 严格验证各场景的冻结材料和情境映射，继续保留原买饮品规则及旧备份兼容。新增材料的人工核对记录见 app/data/README.md。独立通过只说明实际三个任务；没有目标映射或照抄教学材料时，仍显示迁移能力尚未验证。

应用摘要按场景情境、规则版本和内容摘要分别计算并展示，失败只影响同一情境的对应版本；不同情境的通过保持独立。词卡总览表示至少一个指定情境存在证据，详情列出每个情境的结论，不把所有情境混成一次成绩。

EL-15 边界修订引入 introduction-v2，保留原 v1 文件及规则摘要。规则加载检查身份、三轮、唯一任务键、目标映射、标准表达和模板；V3 按保存的规则版本解析，只允许登记过的完整材料。旧结果可读、原提交回放不受新规则影响，新作答在规则变更后返回 409；旧版本的成功只显示对应版本的历史证据，不能作为新版成功。

`SCENE_EXPANSIONS_ENABLED=false` 并重启，仅关闭自我介绍和问路的新轮次：买饮品仍能创建，原标识创建确认、已有轮次作答/读取/导出/恢复均保持；新场景应用摘要标为历史，买饮品证据保持。前端从当前目录能力控制“新开一轮”，不用缓存提交响应中的旧能力开关决定可见入口。恢复 true 可逆开启，不修改表结构、不清数据；`SCENES_ENABLED=false` 的原整体回退继续可用。

最终 Spec 审查复现地点槽位把 “I am from I am” 误作通过，修订为 introduction-v3，并完整保留 v2 原文件。v3 对明显不含姓名/地点的语法片段保持未判定；不扩展认可表达，也不把此类未判定当作专名拼写错误。v1/v2 原 verdict 可恢复和回放，但不作为当前 v3 应用证据。角色模板还需检查嵌入的标准表达，避免仅排除整段等于答案而漏掉中文前缀。

Spec 复审进一步发现 I'm 等缩写绕过同一槽位边界，追加 introduction-v4：槽位语法词与缩写结尾检查由材料中的 check_grammar_tokens 显式启用，旧版本缺失该标记时维持原判定，不能用新 tokenizer 重判旧证据。v3 也按原字节归档，v1–v3 均有恢复/回放回归；新规则仍保留 O’Connor 与 Jean-Luc 等姓名表达。

## EL-16：保存后的受约束角色表达

模型只负责表达已存首答的结果。保存答案与规则判定的事务先提交，反馈请求随后读取同一 scene/session/item/first-attempt 和冻结规则；释放读取会话后调用现有 `generate_json` 与 BULK 路由。外部调用期间不持有 SQLite 写锁；返回后在 `run_write` 内重新核对归属、首答指纹及整个场景的当前修订。过时内容返回 404/409，原答案与后续轮次仍保留；模型不改 verdict、任务、轮次、应用证据或 FSRS。

`scene-feedback-v1` 将角色回应限制在对应场景、任务和已存结果的有限表达材料内；这是对情境校验的保守选择，词汇白名单本身无法判断语义。模型可选不同表达；本地再校验短文本、词形、规范化标准答案泄露和唯一纠正。纠正只允许使用冻结任务的原纠正（明确不满足时），未知/跳过/认可不新增纠正。模型分数、verdict 或轮次指令均无权威；无配置、网络错误、空/非法 JSON 或越界回复使用固定模板。

`scene_feedback` 为每题首答保存一份不可变表达，独立于 `scene_attempts`：operation_id、session/item/attempt UUID、规则版本与摘要、反馈版本、text、可空 correction、origin 和服务端时间。相同操作回放先于内容失效检查；同操作换题 409，新标识确认同题返回原反馈，不重新生成或推进。并发由 BEGIN IMMEDIATE 和唯一约束收口；数据库保存失败整体回滚，浏览器保留反馈标识供重试。

反馈生成、保存、读取都不算接触。浏览器以相同题目组件接收回应，卸载后丢弃 UI 更新；只有回复进入可见视口后才按实际词形记录 source=scene 接触。记录失败使用既有稳定接触身份继续确认；切换轮次折叠旧回复，切换场景卸载旧组件，晚到表达不能写到新场景。

V3 当票登记新集合，校验首答/题目/场景关系、规则摘要、材料版本、回复与单个纠正以及缓存中已有的反馈快照；恢复保留业务 UUID，无本地词卡整数 ID 需要映射。新集合缺失沿既有预览列为缺失，旧场景保持可读，不生成历史反馈或成绩。迁移仅新增表，降级拒绝删表；后续材料版本必须保留此版以支持恢复。
