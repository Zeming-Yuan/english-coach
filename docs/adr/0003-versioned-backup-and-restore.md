# ADR-0003：版本化完整备份与恢复契约

- 状态：已采纳
- 日期：2026-10-30
- 票据：EC-10（导出）；EC-11/EC-12 复用本格式的恢复部分

## 背景

旧 `GET /api/export/cards` 只包含词卡、当前复习行、记忆法、错词四类数据，缺少学习事件、
迁移基线、困难词、课程、故事及词卡关联；导入侧按单词文本映射，会把同词的单词卡与句子卡
合并。恢复切片尚未实现，因此不能直接改变旧导出形状，否则会破坏既有往返测试与旧文件兼容。
备份需要一次逻辑一致的快照、稳定的实体标识和可比较的内容摘要，供后续恢复票复用。

## 决策

1. **新增 `GET /api/export/backup` 作为 V2 完整格式。** 顶层字段固定为
   `version=2`、`exported_at`、`learning_timezone`、`cards`、`reviews`、
   `learning_events`、`review_baselines`、`memos`、`errors`、`hard_cards`、
   `lessons`、`stories`、`story_words`。
2. **只导出白名单模型。** 集合与模型一一对应：`Card`、`Review`、`ReviewEvent`、
   `ReviewBaseline`、`Memo`、`ErrorCard`、`HardCard`、`Lesson`、`Story`、
   `StoryWord`。行字段与模型业务列一致，新增列自动进入备份；不遍历任意表，也不导出
   `Settings`、`alembic_version`、签名密钥、环境配置、语音缓存或浏览器偏好。
3. **实体标识用于引用。** 每个集合内 `id` 唯一；`reviews.card_id`、
   `learning_events.card_id`、`review_baselines.card_id`、`memos.card_id`、
   `errors.card_id`、`hard_cards.card_id`、`story_words.story_id/card_id` 均引用
   备份内的稳定 `id`。同词不同卡型是不同 `Card.id`，恢复时不得按单词文本合并。
   事件缓存响应与 `command_json` 保留原 ID 与题目 token，供恢复映射和回放；签名密钥
   不在数据库中，因此不进入备份。基线 `raw` 保持原始审计数据，活引用由外层 `card_id`
   单独映射。
4. **一次逻辑一致的快照。** 干净会话显式 `BEGIN` 读事务后读取全部集合；调用者已有
   事务时复用、不自行 commit。任何集合之间不提交，避免导出半份状态。
5. **导出时间与时区来自 Runtime。** `exported_at` 是 aware UTC ISO 时间，
   `learning_timezone` 是本次运行的学习时区；它们描述导出环境，不属于业务内容。
6. **语义比较与摘要。** `semantic_snapshot(payload)` 仅排除 `exported_at`；
   `snapshot_revision(payload)` 保留学习事件数组的保存次序，其他集合按 `id` 排序；
   剔除导出时间、按排序键序列化后
   取 SHA256。固定样本
   `{"version":2,"learning_timezone":"Asia/Shanghai","cards":[{"id":1,"word":"apple"}],...}`
   的摘要在 `tests/test_backup_v2.py` 固定为
   `4de0c10ff9d3247203427baba022721f1ae79c1e2092bb0eb92ecc405cdddca2`，
   后续恢复票必须使用同一契约。EC-14 明确事件导出按 `occurred_at`、SQLite `rowid`
   排列，恢复按数组次序写入，保证同时间戳的先后不会因随机 UUID 排序而变化；
   已导出的旧文件若已丢失该先后，只能保留文件现有次序，不能反推。
7. **旧导出保留为兼容面。** `GET /api/export/cards` 与 Anki CSV 保持原形状，
   不宣称完整备份；EC-10 不改变旧导入行为，已有往返测试继续通过。新旧 URL 并存的
   理由是恢复切片尚未交付：旧导入仍按旧形状消费，提前改变旧导出会破坏已保存的旧文件
   与现有往返测试。
8. **EC-12 全量替换复用恢复协调器。** `/api/import/preview` 返回 `mode=full_replace`、备份各集合数量、目标各集合替换数量和当前修订；无版本号文件继续 `legacy_partial`。完整校验全部强类型集合、唯一 ID、嵌套提交/缓存及全部活引用后才进入写事务。命令会话/自评分必须与外层事件一致，缓存答案使用实际评分的规范化规则比较；外层可空会话 UUID 按其值验证后规范保存，原输入载荷摘要及原命令语义保持不变。
9. **保护现有进度后替换。** V2 执行必须携带预览返回的 `expected_revision` 字符串，缺失或非法类型在任何副本/写入前返回 422；无版本号旧文件仍兼容部分恢复。`BEGIN IMMEDIATE` 内重读修订；预览后发生新学习返回 409。安全副本先原子写盘并 fsync，再依赖逆序删除、父表优先插入；提交失败整体回滚，安全副本保留。空备份也需同样预览与显式确认。
10. **恢复的身份与回放。** 词卡使用 SQLite 原生 `AUTOINCREMENT` 分配新 ID；迁移 `ec12_card_identity` 保留全部原字段、ID、索引与入站关联，将退役 ID 高水位保存在原生 `sqlite_sequence` 中。空备份替换、重启、再恢复和普通加词均不复用这些卡 ID，避免恢复前已启动的 AI 结果命中替换后的卡。其他整数实体在替换内映射为新 ID。事件/提交 UUID 保留；活 `card_id/story_id`、已验题目上下文、缓存 `card_id/sentence_card_id` 映射后重算规范化指纹。基线外层活引用映射，`raw/source_review_id` 历史证据原样保留。
11. **旧签名不重新验证已保存的提交。** 签名密钥不恢复。原提交标识、原 token 和映射后的相同业务内容通过已保存的已验上下文回放缓存，不再次排期；不同内容 409，新提交或换 token 仍需目标实例验签。重复全量恢复保持业务等价，但不能用它覆盖恢复后新增的学习进度。

## 后果

- 备份文件体积随学习事件增长；这是完整历史可恢复的代价。
- 恢复逻辑必须按集合 ID 建立旧→新映射，并保留幂等提交标识；不能退回按单词文本恢复。
- 导出时间不参与业务等价比较；数据库内部自增 ID 在恢复后会重新映射，但备份内引用
  始终自洽。

## 回退

可隐藏设置中的下载入口或回到旧导出视图，但必须保留 V2 读取契约与已产生文件；
不得把旧的不完整导出重新标为完整备份，也不得以旧快照覆盖新学习数据。


## EC-12 身份保护与版本回退边界

词卡分配器的高水位属于目标数据库的运行元数据，不进入学习内容备份，也不随全量替换删除。原生序列的写入与对应词卡插入同事务，失败会回滚；失败替换没有提交新内容，也不会把已有退役高水位降回去。迁移沿现有先备份再升级路径，通过批量复制保留业务行与引用，随后检查完整外键图。

迁移的 downgrade 保留 `AUTOINCREMENT` 与序列数据；再次 upgrade 检测已采用原生分配器时不重建空表，保留高水位。版本回退到显式写入 `MAX(id)+1` 的旧恢复代码会绕过原生分配器，不能再保证旧后台结果不会命中新内容。不得带着未结束的后台写入恢复旧写路径；保留数据与序列，停止旧写入并前向升级修复，不用旧快照覆盖恢复后新增进度。

## EC-15：恢复与单卡当前状态

V2 的 `reviews.card_id` 必须唯一；预览和执行都在安全副本/数据写入之前拒绝重复当前状态，返回带 `reviews/card_id` 的 422。V1 旧部分恢复继续归档每个旧源行、选择最新有效状态并更新唯一当前行，重复导入不覆盖后来进度。原始 baseline `raw/source_review_id` 继续作为历史证据保留，contract 归档不冒充真实作答。收口迁移及其 downgrade 不重建 cards、不降低原生序列高水位。
