## 用户可观察的行为 / What to build

学习者连续评分后能在词卡详情看到新增的评分轨迹；已有排期和旧入口仍可使用，旧历史缺失被明确标注。

## Blocked by

- EC-01：全新安装和旧库升级后能打开真实首页

## 涉及的相关层

加法式 schema、旧状态迁移基线、评分 API、词卡详情查询/UI、真实升级与浏览器测试。

## 验收条件

- [ ] 定义并增加当前记忆状态与追加事件的稳定契约，包含来源、题型、时间/时区、提示、可空正误、自评分、是否排期、提交标识及排期摘要；物理组织不要求重命名旧表或另建双写状态表。
- [ ] 保留旧结构与调用兼容面，旧状态和多行来源可追溯；迁移基线保留原累计次数与有效最后时间，不按次数伪造事件。
- [ ] 先接入现有显式评分 HTTP 入口：当前排期更新与新评分轨迹在一次事务中提交；详情能看到两次真实新提交，不再把一行当前状态当完整历史。
- [ ] 尚不能辨认来源或提示情况的旧请求标为未分类，不纳入独立提取正确率或自适应样本；其他未迁移入口保持现有行为并明确覆盖边界。
- [ ] 保留旧消费者可读的当前排期；新关联的删除和已有词卡删除行为相容，不留下悬空关系。
- [ ] 提供单一学习提交模块的原子、幂等扩展契约及基础pending存储工具供后续迁移独立使用；完整页面刷新恢复闭环由EC-04负责。本票不通过提前切换全部页面来完成扩展。

## 验证命令

在仓库根目录、已安装项目依赖并激活 Python 虚拟环境后执行。E2E 入口及 --ticket 选择由 EC-01 建立；以下是本票交付后必须通过的命令，不是现状通过声明。每票自行注册场景，空匹配必须失败。

```bash
npm --prefix frontend run test:e2e -- --ticket EC-03
python -m pytest -q
```

最高测试 seam：浏览器 → 真实 FastAPI → Alembic 迁移建立的隔离 SQLite。只替换 AI/TTS 外部服务，失败路径可注入传输/事务故障；成功的应用保存和读取不伪造 API。

## 独立验收方式

升级含旧数据的隔离实例，打开一张卡并通过现有评分入口连续提交两次；详情显示两条新轨迹和旧历史不完整提示，原队列仍可使用。

只需要本票及其已完成阻塞票，不依赖尚未完成票补齐本票行为。固定数据通过隔离测试准备，不能以用户数据或真实 AI 作为前提。

## 明确不做

不宣称全部入口历史已完整、不交付完整的页面刷新恢复闭环（由 EC-04 负责）、不切换统计、自适应或全部练习语义；不删除旧结构。

## 回退方式

撤回事件显示和新调用适配，保留加法式表/字段与已经追加的事件；前版继续读取兼容的当前状态。不得降级时删除新事件。

如后续消费者已经落地，先按依赖逆序回退，或保留公共兼容面并关闭本票入口；任何回退都不能抹除后续新增学习数据。事务故障回滚与版本回退分别验收，不混为一谈。
