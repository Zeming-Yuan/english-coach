## 用户可观察的行为 / What to build

所有已保留的入口及历史/备份读取使用同一套记录规则；升级前后用户结果一致，旧代码分支不再悄悄改写进度。

## Blocked by

- EC-07：迁移混合练习：同题同规则，一次操作只记录一次
- EC-09：区分正确率与自评通过率，可靠调节新词量
- EC-12：完整备份恢复到另一实例后继续学习

## 涉及的相关层

状态唯一性约束、全部学习写入/读取适配、统计/备份兼容、公开 API、跨入口回归和兼容演练。

## 验收条件

- [ ] 确认自评分、输入、选择、混合、历史/指标及两种恢复路径均迁移；审计推荐、故事选词、词卡详情/删除、毕业检查与后台任务，不留直接绕过统一规则的业务写入。
- [ ] 对当前记忆状态收紧单卡唯一性；遗留多行先保留可追溯基线再归并，不删除真实新增事件。
- [ ] 移除重复的排期/错词/旧历史计算分支；旧端点 URL 与必要响应字段继续通过薄适配器工作，不能把 contract 理解为删除公共端点。
- [ ] 新备份继续可读，旧备份兼容导入继续安全；旧无标识调用的有限兼容保留，分类未知的数据不进入可靠统计。
- [ ] 仅删除已无消费者的内部业务形式；本次不物理删除承载历史兼容的旧字段/数据。收紧约束和旧代码删除分别可撤回。
- [ ] 全局回归保持绿色，不依赖等待最后一张票才恢复可运行。

## 验证命令

在仓库根目录、已安装项目依赖并激活 Python 虚拟环境后执行。E2E 入口及 --ticket 选择由 EC-01 建立；以下是本票交付后必须通过的命令，不是现状通过声明。每票自行注册场景，空匹配必须失败。

```bash
npm --prefix frontend run test:e2e -- --ticket EC-15
python -m pytest -q
```

最高测试 seam：浏览器 → 真实 FastAPI → Alembic 迁移建立的隔离 SQLite。只替换 AI/TTS 外部服务，失败路径可注入传输/事务故障；成功的应用保存和读取不伪造 API。

## 独立验收方式

在升级样本上遍历每种评分与恢复入口，查看队列、详情、统计、故事选词与删除结果；比较 contract 前后公开业务快照与备份，演练放松新增约束后兼容运行。

只需要本票及其已完成阻塞票，不依赖尚未完成票补齐本票行为。固定数据通过隔离测试准备，不能以用户数据或真实 AI 作为前提。

## 明确不做

不把剩余每日 UI 细节作为前置阻塞，不新增物理破坏性清库/删表迁移，不删除公共评分端点或备份兼容能力。

## 回退方式

撤回约束收紧及内部旧代码删除时保留新接口、事件和基线；必要时恢复兼容实现，不恢复重复业务写入。若后续已依赖最终契约，先回退消费者或前向修复。

如后续消费者已经落地，先按依赖逆序回退，或保留公共兼容面并关闭本票入口；任何回退都不能抹除后续新增学习数据。事务故障回滚与版本回退分别验收，不混为一谈。
