## 用户可观察的行为 / What to build

用户把新版备份恢复到另一个实例，词卡、学习进度、事件和内容关联完整等价；失败时目标实例保持原状。

## Blocked by

- EC-04：迁移自评分：保存确认、幂等重试与刷新恢复
- EC-11：旧备份导入不串卡，失败不清空原进度

## 涉及的相关层

完整格式校验、全实体 ID 映射、恢复事务/API、影响预览与确认 UI、双实例浏览器验收。

## 验收条件

- [ ] 新版恢复明确为全量替换，预览包含数量与目标内容替换影响；显式确认之前不改变数据库，取消和空备份也走明确分支。
- [ ] 校验全部集合及引用后，在恢复协调事务中重建所有数据库学习内容；提交才显示成功。
- [ ] 同词两卡型各自保留状态和关联；事件提交标识及幂等结果中引用的实体 ID 均正确映射。
- [ ] 恢复前备份必须可用；未知版本、非法字段/ID/关系、预备份失败和写入中途故障均安全失败，原数据不变。
- [ ] 另一个真实迁移实例中恢复后可继续评分，重试恢复来的提交不重复排期；重复全量恢复保持业务等价。

## 验证命令

在仓库根目录、已安装项目依赖并激活 Python 虚拟环境后执行。E2E 入口及 --ticket 选择由 EC-01 建立；以下是本票交付后必须通过的命令，不是现状通过声明。每票自行注册场景，空匹配必须失败。

```bash
npm --prefix frontend run test:e2e -- --ticket EC-12
python -m pytest -q
```

最高测试 seam：浏览器 → 真实 FastAPI → Alembic 迁移建立的隔离 SQLite。只替换 AI/TTS 外部服务，失败路径可注入传输/事务故障；成功的应用保存和读取不伪造 API。

## 独立验收方式

从实例 A 经浏览器导出全部内容，在不同 ID 布局的实例 B 预览并恢复；比较公开业务结果，重试一条既有提交并新增一次作答；再演练拒绝与回滚。

只需要本票及其已完成阻塞票，不依赖尚未完成票补齐本票行为。固定数据通过隔离测试准备，不能以用户数据或真实 AI 作为前提。

## 明确不做

不恢复密钥/浏览器偏好，不支持未来未知版本，不引入跨库交互合并或云同步。

## 回退方式

关闭新版替换入口而保留数据及格式兼容；如需纠正恢复结果，先保护恢复后新增进度，不能直接用旧快照覆盖。前版仅在兼容读取验证通过后可运行。

如后续消费者已经落地，先按依赖逆序回退，或保留公共兼容面并关闭本票入口；任何回退都不能抹除后续新增学习数据。事务故障回滚与版本回退分别验收，不混为一谈。

T14–T17 的新版格式部分、T21；AC07、AC08、AC09、AC11。
