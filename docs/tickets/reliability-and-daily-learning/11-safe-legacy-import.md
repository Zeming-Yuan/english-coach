## 用户可观察的行为 / What to build

持有无版本号旧备份的用户能预览并安全恢复其中包含的内容；非法数据、歧义匹配或写入失败不损坏当前词库。

## Blocked by

- EC-10：从界面导出完整、带版本的数据库备份

## 涉及的相关层

旧格式校验与身份映射、统一恢复事务/写入串行化、恢复 API、预览/确认/取消 UI、故障注入测试。

## 验收条件

- [ ] 识别旧版部分恢复并展示范围；先按备份 ID 区分卡型，再按单词和卡型匹配目标；歧义或悬空关系明确 422 拒绝。
- [ ] 只更新备份覆盖的关联卡片与字段，未包含的课程、故事等不清空；重复导入不重复创建。
- [ ] 先完成全量校验，再一次事务写入；非法 state/数值/日期或中途故障不会留下已删除的复习、记忆法或错词。
- [ ] 执行前产生可用恢复前备份并告知位置/下载方式，失败就不替换；用户取消不写入。
- [ ] 旧复习转换为当前状态与不完整历史基线，不伪造事件；恢复与普通学习写入串行，成功后可继续学习。

## 验证命令

在仓库根目录、已安装项目依赖并激活 Python 虚拟环境后执行。E2E 入口及 --ticket 选择由 EC-01 建立；以下是本票交付后必须通过的命令，不是现状通过声明。每票自行注册场景，空匹配必须失败。

```bash
npm --prefix frontend run test:e2e -- --ticket EC-11
python -m pytest -q
```

最高测试 seam：浏览器 → 真实 FastAPI → Alembic 迁移建立的隔离 SQLite。只替换 AI/TTS 外部服务，失败路径可注入传输/事务故障；成功的应用保存和读取不伪造 API。

## 独立验收方式

浏览器两次导入含同词不同卡型的旧备份，确认不串卡、不擦除额外故事；分别注入非法字段、备份失败与事务中途异常，原数据保持可用。

只需要本票及其已完成阻塞票，不依赖尚未完成票补齐本票行为。固定数据通过隔离测试准备，不能以用户数据或真实 AI 作为前提。

## 明确不做

不实现新版全量替换恢复，不增加交互式冲突合并，不补造旧备份缺失的内容。

## 回退方式

可关闭旧版导入入口，同时保留校验与原子保护及已恢复的数据；不重新启用会先删后校验的旧实现。恢复前副本不能覆盖恢复后新产生的进度。

如后续消费者已经落地，先按依赖逆序回退，或保留公共兼容面并关闭本票入口；任何回退都不能抹除后续新增学习数据。事务故障回滚与版本回退分别验收，不混为一谈。

T15–T17 的旧格式部分、T21；AC08、AC09、AC11。
