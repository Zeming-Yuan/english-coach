## 用户可观察的行为 / What to build

学习者按配置模板和文档启动应用，空库、已有旧库及自定义数据库位置均能进入首页；缺少 AI 密钥只影响 AI 功能。

## Blocked by

None（可立即开始）。

## 涉及的相关层

配置与模型客户端初始化、数据库迁移、首页 API、加载/错误 UI、安装说明、浏览器与迁移测试。

## 验收条件

- [ ] 统一 LLM 配置、模型路由与模板；旧配置给出迁移说明，冲突和不可写数据库明确报错且不输出密钥。
- [ ] 通过新增向前迁移修复缺评分字段，包括旧迁移已标记完成但实际缺列的数据库；应用与迁移使用同一数据库地址。
- [ ] 升级前留可恢复副本；旧词卡和排期保留，重复升级不改业务数据；无密钥时首页及已有内容可用，AI 操作说明未配置。
- [ ] 建立隔离的浏览器验收命令、真实迁移与外部替身，支持 --ticket EC-XX 选择已交付场景；无匹配场景、断言失败或必经步骤未执行必须非零退出。
- [ ] 入口执行本次前端构建，自动管理独立数据库、端口、下载目录与进程；不要求本机 Edge 或正式服务器预先启动。

## 验证命令

在仓库根目录、已安装项目依赖并激活 Python 虚拟环境后执行。E2E 入口及 --ticket 选择由 EC-01 建立；以下是本票交付后必须通过的命令，不是现状通过声明。每票自行注册场景，空匹配必须失败。

```bash
npm --prefix frontend run test:e2e -- --ticket EC-01
python -m pytest -q
```

最高测试 seam：浏览器 → 真实 FastAPI → Alembic 迁移建立的隔离 SQLite。只替换 AI/TTS 外部服务，失败路径可注入传输/事务故障；成功的应用保存和读取不伪造 API。

## 独立验收方式

在干净数据目录用空密钥启动并打开首页；在旧迁移缺列样本上升级、查看原词卡并完成一次现有评分；另用自定义数据库地址重复操作。

只需要本票及其已完成阻塞票，不依赖尚未完成票补齐本票行为。固定数据通过隔离测试准备，不能以用户数据或真实 AI 作为前提。

## 明确不做

不引入新事件模型、不做入门词包、不修复全部练习提交；不升级全部依赖。

## 回退方式

撤回启动与配置改动时保留向前修复的兼容字段。先验证前版可以读取修复后的库；不通过删除用户数据重建旧库。恢复迁移前副本仅用于隔离演练或升级未产生新数据的失败恢复。

如后续消费者已经落地，先按依赖逆序回退，或保留公共兼容面并关闭本票入口；任何回退都不能抹除后续新增学习数据。事务故障回滚与版本回退分别验收，不混为一谈。
