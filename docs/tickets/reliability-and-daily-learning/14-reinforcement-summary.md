## 用户可观察的行为 / What to build

用户完成主队列后，可以为本轮薄弱词做最多三题巩固或明确跳过，最终看到只基于已保存结果的完成反馈。

## Blocked by

- EC-13：首页一键开始到期优先、目标固定的每日学习

## 涉及的相关层

本轮已保存事件/薄弱词读取、复用输入题提交、阶段编排 API/UI、完成页、边界与故障测试。

## 验收条件

- [ ] 从本轮答错、低分与跳过项生成最多 3 道可作答巩固题，使用已交付的独立/提示规则并保存巩固来源。
- [ ] 零薄弱词、词库过小或无有效题时能正常结束；可明确跳过巩固，不把跳过伪造成答错或掌握。
- [ ] 保存未确认不进入完成页；中途重试沿用稳定标识，题目只计一次。
- [ ] 完成页区分完成词数、独立/辅助/识别结果和跳过项，显示仍薄弱的词与真实已有排期支持的下一步。
- [ ] 不把课程生成算每日完成，不作不会遗忘的保证；TTS/AI 故障不丢已保存进度。

## 验证命令

在仓库根目录、已安装项目依赖并激活 Python 虚拟环境后执行。E2E 入口及 --ticket 选择由 EC-01 建立；以下是本票交付后必须通过的命令，不是现状通过声明。每票自行注册场景，空匹配必须失败。

```bash
npm --prefix frontend run test:e2e -- --ticket EC-14
python -m pytest -q
```

最高测试 seam：浏览器 → 真实 FastAPI → Alembic 迁移建立的隔离 SQLite。只替换 AI/TTS 外部服务，失败路径可注入传输/事务故障；成功的应用保存和读取不伪造 API。

## 独立验收方式

主队列分别产生零个与多个薄弱词，演示最多三题、主动跳过、少词量与保存故障；完成页结果能与本轮已提交结果核对。

只需要本票及其已完成阻塞票，不依赖尚未完成票补齐本票行为。固定数据通过隔离测试准备，不能以用户数据或真实 AI 作为前提。

## 明确不做

不新增新的题型、无限练习或智能课程生成；不要求完成巩固才允许离开。

## 回退方式

关闭巩固阶段，主队列仍可直接到兼容完成页；保留已经写入的巩固事件及来源，不重算或删除。

如后续消费者已经落地，先按依赖逆序回退，或保留公共兼容面并关闭本票入口；任何回退都不能抹除后续新增学习数据。事务故障回滚与版本回退分别验收，不混为一谈。
