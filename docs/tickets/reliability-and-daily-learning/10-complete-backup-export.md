## 用户可观察的行为 / What to build

用户从设置下载包含完整数据库学习内容的版本化备份，并能看清哪些数据包含、哪些不包含。

## Blocked by

## 涉及的相关层

一致性数据快照、实体/关联序列化、导出 API、设置备份 UI/下载、浏览器和公开格式检查。

## 验收条件

- [ ] 格式包含版本、有效导出时间、学习时区；覆盖全部词卡字段、当前状态、事件/去重结果、迁移基线、记忆法、错词、困难词、课程、故事及关联。
- [ ] 使用备份内稳定实体标识表达关系，同词不同卡型独立；导出形成一次逻辑一致快照。
- [ ] 界面有可发现的备份入口、成功下载和失败反馈；说明不含密钥、环境、语音缓存和浏览器偏好。
- [ ] 预留明确的恢复影响预览信息契约，供后续恢复使用；不得把尚未交付的恢复按钮显示成可用。
- [ ] 固定版本格式和校验样本，后续恢复票使用同一契约；原 Anki 导出保留。

## 验证命令

在仓库根目录、已安装项目依赖并激活 Python 虚拟环境后执行。E2E 入口及 --ticket 选择由 EC-01 建立；以下是本票交付后必须通过的命令，不是现状通过声明。每票自行注册场景，空匹配必须失败。

```bash
npm --prefix frontend run test:e2e -- --ticket EC-10
python -m pytest -q
```

最高测试 seam：浏览器 → 真实 FastAPI → Alembic 迁移建立的隔离 SQLite。只替换 AI/TTS 外部服务，失败路径可注入传输/事务故障；成功的应用保存和读取不伪造 API。

## 独立验收方式

准备含同词两卡型及全部关联的迁移库，在浏览器下载备份；经公开格式校验确认范围、关联和时间，并模拟导出失败。

只需要本票及其已完成阻塞票，不依赖尚未完成票补齐本票行为。固定数据通过隔离测试准备，不能以用户数据或真实 AI 作为前提。

## 明确不做

不执行新格式恢复、不改变旧导入行为、不把文件拷贝当作完整恢复验收。

## 回退方式

撤回新下载入口或回到旧导出视图，保留已产生备份文件和新格式读取契约，不能把旧不完整导出继续标为完整备份。

如后续消费者已经落地，先按依赖逆序回退，或保留公共兼容面并关闭本票入口；任何回退都不能抹除后续新增学习数据。事务故障回滚与版本回退分别验收，不混为一谈。
