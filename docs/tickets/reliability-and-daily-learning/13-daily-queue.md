## 用户可观察的行为 / What to build

用户打开首页就能开始今日学习：先完成到期词，再学配额内新词；任务量明确，专项练习仍可找到。

## Blocked by

- EC-09：区分正确率与自评通过率，可靠调节新词量

## 涉及的相关层

队列查询和去重、现有记忆状态/推荐读取、今日 API、首页/学习编排 UI、浏览器测试。

## 验收条件

- [ ] 主按钮突出每日学习；专项练习收纳至次级入口，既有功能不移除。
- [ ] 到期词优先，同组错词/困难词优先；单轮最多 20 张到期复习，其余数量可见并可继续下一轮，随后加入推荐配额内新词。
- [ ] 同卡多种标签或池来源不造成主队列重复；本轮目标开始时固定，队列缩短不降低目标。
- [ ] 完成目标与新词配额分别展示，遵循样本门槛与下调规则；已完成复习、空词库和加载错误各有明确入口。
- [ ] 保持保存确认后才推进的语义，词量较少也可正常完成。

## 验证命令

在仓库根目录、已安装项目依赖并激活 Python 虚拟环境后执行。E2E 入口及 --ticket 选择由 EC-01 建立；以下是本票交付后必须通过的命令，不是现状通过声明。每票自行注册场景，空匹配必须失败。

```bash
npm --prefix frontend run test:e2e -- --ticket EC-13
python -m pytest -q
```

最高测试 seam：浏览器 → 真实 FastAPI → Alembic 迁移建立的隔离 SQLite。只替换 AI/TTS 外部服务，失败路径可注入传输/事务故障；成功的应用保存和读取不伪造 API。

## 独立验收方式

准备超过 20 张到期词和有重叠标签的新词，浏览器完成一轮；确认先后顺序、去重、固定目标与剩余入口，再测试已完成/空库/失败状态。

只需要本票及其已完成阻塞票，不依赖尚未完成票补齐本票行为。固定数据通过隔离测试准备，不能以用户数据或真实 AI 作为前提。

## 明确不做

不在本票实现最多三题巩固或最终成绩页，不更改课程体系或句子卡排期。

## 回退方式

恢复旧入口布局但保留队列/推荐公开契约和已保存事件；本轮中途切换版本须明确退出到首页，不能伪造完成。

如后续消费者已经落地，先按依赖逆序回退，或保留公共兼容面并关闭本票入口；任何回退都不能抹除后续新增学习数据。事务故障回滚与版本回退分别验收，不混为一谈。

## 规格覆盖

T18、T20/T21 的每日队列部分；AC10、AC11、AC14。
