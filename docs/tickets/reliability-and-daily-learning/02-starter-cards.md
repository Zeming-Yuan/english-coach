## 用户可观察的行为 / What to build

首次使用者主动加载 10 张已核对的入门词卡，直接开始学习；老用户词库不被自动填充。

## Blocked by

- EC-01：全新安装和旧库升级后能打开真实首页

## 涉及的相关层

固定内容数据、词卡写入 API、首次使用 UI、现有闪卡流程、浏览器测试。

## 验收条件

- [ ] 显式操作添加 10 张核对过释义、音标和例句的词卡，界面说明这是入门体验内容。
- [ ] 按单词和卡型处理已有卡；重复操作不重复创建，不改写已有自定义内容，不自动给老用户添加。
- [ ] 成功后可以马上进入真实学习；无密钥或外部服务不可用不阻断本地入门操作。
- [ ] 添加失败区分于空词库，提供重试；移动与桌面入口都可操作。

## 验证命令

在仓库根目录、已安装项目依赖并激活 Python 虚拟环境后执行。E2E 入口及 --ticket 选择由 EC-01 建立；以下是本票交付后必须通过的命令，不是现状通过声明。每票自行注册场景，空匹配必须失败。

```bash
npm --prefix frontend run test:e2e -- --ticket EC-02
python -m pytest -q
```

最高测试 seam：浏览器 → 真实 FastAPI → Alembic 迁移建立的隔离 SQLite。只替换 AI/TTS 外部服务，失败路径可注入传输/事务故障；成功的应用保存和读取不伪造 API。

## 独立验收方式

在空库中不配置密钥，加载两次入门词卡，确认只有一组内容并完成一次学习；在含同名自定义词卡的库中重复，确认原内容未改变。

只需要本票及其已完成阻塞票，不依赖尚未完成票补齐本票行为。固定数据通过隔离测试准备，不能以用户数据或真实 AI 作为前提。

## 明确不做

不扩展课程体系、不增加词包管理系统、不调整每日队列和学习记录架构。

## 回退方式

隐藏入门入口并撤回固定内容添加能力，保留已添加词卡及其学习数据；不批量删除曾由入门包创建的卡片。

如后续消费者已经落地，先按依赖逆序回退，或保留公共兼容面并关闭本票入口；任何回退都不能抹除后续新增学习数据。事务故障回滚与版本回退分别验收，不混为一谈。
