# EL-04：Expand：看词卡或听答案后，能核对最近一次应用内接触

- **状态：** 已确认粒度与阻塞关系；ready-for-agent；产品未实施。
- **发布标签：** 直接使用 `ready-for-agent`，不重复 triage；有阻塞的票仍须等待前置完成。
- **阶段：** expand：接触记录与确认。
- **来源：** [EnglishCoach：可验证学习效果与个性化训练规格](../../specs/evidence-based-personalized-learning.md)。
- **范围：** F4、F1。本地 EL 编号不是 GitHub issue 编号，也不是现有命令的过滤参数。

## 用户可观察的行为 / What to build

学习者在详情或词表实际看到目标词、实际播放答案后，能够核对应用内接触依据；接触记录不被当作作答或完成量。

只列真正的前置行为或接口，不将阶段顺序、共享文件冲突或便于排程当成业务阻塞。依赖从祖先传递，不重复列间接前置。

## 验收条件

- [ ] 增加接触记录的服务端确认能力，记录目标身份、修订、来源及服务端时间；以词卡详情/词表实际展示和答案播放完成首条垂直路径。
- [ ] 预取、缓存预热和未展示内容不算接触；真实播放与失败播放有明确处理，不用请求音频本身伪造用户听过。
- [ ] 发送前保存本地待确认标记，成功后清理；重复确认去重，刷新后可继续确认。失败或存储不可用时标注间隔依据不完整。
- [ ] 延迟确认以服务端确认时间作为保守依据，不让客户端回填更早日期制造长间隔；接触不写 FSRS、正确率、连续学习日或每日完成。
- [ ] 接触记录及确认身份完整纳入 V3，恢复后时间依据可解释，旧数据缺记录保持未知。

- [ ] 本票路径的保存失败、重复确认、内容修订/删除及恢复边界有可观察结果；不依赖尚未实施的票兜底。
- [ ] 若引入新的持久记录或用途，本票同步实现 V3 导出、校验、引用映射、恢复及旧格式缺失解释；不能只加表后等待最后集成票。
- [ ] 本票新增具名用户级测试分支并登记到完整覆盖门禁，同时维护受影响的现有场景，不降低原有验收要求。

## 涉及的相关层

接触 schema/迁移、确认/幂等 API、词卡详情/词表/TTS 展示事件、pending 恢复、V3 适配、E2E。

涉及层按完成用户路径所需选择；复用现有 schema 的切片不强制新建表。实现位置由当时仓库结构决定，本票不指定易失效的产品源码路径。

## 验证命令

从仓库根目录运行，Python/前端依赖已安装；以下使用当前 Linux 工作区实际存在的虚拟环境入口，无需系统 `python` 别名：

```bash
.venv/bin/python -m pytest -q
npm --prefix frontend run test:e2e
```

E2E 主入口会重新构建并运行桌面/移动视口。每票只要求本票及前置已交付的分支，新增必跑分支须随本票接入覆盖校验；不预登记未来尚不存在的分支导致前置无法合入。本地 EL 标识不能直接传给当前仅接受 EC-NN 的单票过滤参数。若以后增加定向命令，须先实现并验证拒绝未知/空匹配；完整未过滤门禁仍保留。

这些是本票实施后的验证要求，不是本次文档任务已运行产品测试的声明。

最高测试 seam：浏览器用户操作 → 真实 React → 真实 FastAPI → 真实 FSRS/事务 → 经 Alembic 迁移建立的隔离 SQLite。只替换外部 AI/TTS，时钟在启动处注入；正常成功路径不伪造应用 API。公开 HTTP、迁移、并发和恢复测试补充边界。

## 独立验收方式

1. 打开详情、只预取音频、实际播放及打开词表，比较可见的最近接触依据与原作答统计。
2. 中断接触确认后刷新、重试，核对记录只有一份且未被算作学习完成。
3. 恢复包含接触记录的 V3，核对时间和修订。
4. 在本票与所有前置已完成、后继尚未实施的代码状态下执行上述命令，保留真实运行结果、源码/产物身份及失败诊断；按下述方式演练功能回退。

仅依赖本票和其已完成阻塞票即可演示。测试可用隔离夹具准备旧数据和词库，关键成功作答仍从真实入口发生；不得依赖用户数据库或真实付费模型。

## 明确不做

- 不一次迁移所有学习入口，不发放隔日/一周证据，不监控应用外学习。
- 本票不自动发布/部署，不扩大为横向框架重写，不使用 LLM 评价替代既有确定规则。

## 回退方式

停止新增接触上报时将相关间隔展示降为依据不足，保留已确认记录和恢复适配；不把停止记录当作没有接触。

共同边界：已新增的学习、上下文、修订与备份数据继续可读；有后继消费者时按依赖逆序撤回，或保留它们依赖的 API/数据适配。功能回退与事务回滚分别验收。不得以恢复旧快照、删除新字段或清空事件来冒充回退成功。

## 规格覆盖与领域约束

- 规格验收条件：AC21、AC23、AC35、AC36、AC37、AC39。属于共享条件时，本票负责自己路径的完整行为，集成票负责跨路径组合，不替本票补实现。
- 领域规则：当前记忆状态与只追加学习事件分开；独立输入/辅助/识别/自评/跳过保持各自含义；学习日沿用事件写入时归属；旧基线不冒充完整历史。
- ADR-0001 的幂等/先确认后推进、ADR-0002 的日统计边界、ADR-0003 的预览/安全副本/原子恢复适用。涉及本规格已提出的扩展时，在实现中显式增补决策，不静默改写已采纳口径。
