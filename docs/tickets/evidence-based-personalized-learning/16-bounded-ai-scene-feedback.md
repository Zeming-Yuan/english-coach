## 验收条件

- [x] AI 只接收已认可的场景、可用词汇和上一轮结果；不能改轮次、标准答案、任务条件或客观判定。
- [x] 回应超词汇、泄露当前标准应答、缺情境一致性或格式无效时不直接展示，改用核对模板；合格回应实际展示后记录适用接触。
- [x] 每轮最多一个关键纠正；模型称对/错不能改变规则结果，不把未判定改成成功或额外写 FSRS。
- [x] 答案与轮次先保存、AI 后生成；未配置、超时、断连和失败保留结果，重复确认与晚到回应不能重复推进或污染新轮次。
- [x] 模板/模型来源和必要回复版本可追溯并随现有场景记录进入 V3；原有场景无需真实 AI 密钥也可验收。

- [x] 本票路径的保存失败、重复确认、内容修订/删除及恢复边界有可观察结果；不依赖尚未实施的票兜底。
- [x] 若引入新的持久记录或用途，本票同步实现 V3 导出、校验、引用映射、恢复及旧格式缺失解释；不能只加表后等待最后集成票。
- [x] 本票新增具名用户级测试分支并登记到完整覆盖门禁，同时维护受影响的现有场景，不降低原有验收要求。

## 验证命令

从仓库根目录运行，Python/前端依赖已安装；以下使用当前 Linux 工作区实际存在的虚拟环境入口，无需系统 `python` 别名：

```bash
.venv/bin/python -m pytest tests/test_el16_bounded_ai_scene_feedback.py -q
npm --prefix frontend run test:e2e -- --ticket EL-16
```

E2E 主入口会重新构建并运行桌面/移动视口。当前 runner 已支持 EL 单票过滤并拒绝未知/空匹配。本轮按用户要求只验证本票与受影响回归；完整命令、运行身份、浏览器环境及未验证项见验收证据，未过滤门禁仍保留。

各项验收的执行结果以验收证据为准；本地完成不代表已合入、发布或关闭 GitHub Issue。

最高测试 seam：浏览器用户操作 → 真实 React → 真实 FastAPI → 真实 FSRS/事务 → 经 Alembic 迁移建立的隔离 SQLite。只替换外部 AI/TTS，时钟在启动处注入；正常成功路径不伪造应用 API。公开 HTTP、迁移、并发和恢复测试补充边界。

## 独立验收方式

1. 用可控提供方返回合格回复、越界词、泄露答案和误判，核对只有合格内容直接展示且判定未变。
2. 在保存后制造 AI 超时并切换场景，确认模板可继续、旧回复不覆盖新场景。
3. 在本票与所有前置已完成、后继尚未实施的代码状态下执行上述命令，保留真实运行结果、源码/产物身份及失败诊断；按下述方式演练功能回退。

仅依赖本票和其已完成阻塞票即可演示。测试可用隔离夹具准备旧数据和词库，关键成功作答仍从真实入口发生；不得依赖用户数据库或真实付费模型。

## 明确不做

- 不做无限聊天或 LLM 权威评分，不等待模型反馈才保存答案，不包含 ASR。
- 本票不自动发布/部署，不扩大为横向框架重写，不使用 LLM 评价替代既有确定规则。

## 回退方式

关闭模型增强并使用既有核对模板，已存答案、轮次和结果保留，不需迁移回旧格式。

共同边界：已新增的学习、上下文、修订与备份数据继续可读；有后继消费者时按依赖逆序撤回，或保留它们依赖的 API/数据适配。功能回退与事务回滚分别验收。不得以恢复旧快照、删除新字段或清空事件来冒充回退成功。
