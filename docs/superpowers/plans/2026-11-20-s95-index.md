## 并行开发与串行合入

- [#97](https://github.com/Zeming-Yuan/english-coach/issues/97) 与 [#99](https://github.com/Zeming-Yuan/english-coach/issues/99) 共用单词卡身份和写事务。[#99](https://github.com/Zeming-Yuan/english-coach/issues/99) 与 [#102](https://github.com/Zeming-Yuan/english-coach/issues/102) 都会调整添加页。分别完成真实入口的验收，再逐一整合。
- [#98](https://github.com/Zeming-Yuan/english-coach/issues/98)、[#100](https://github.com/Zeming-Yuan/english-coach/issues/100)、[#101](https://github.com/Zeming-Yuan/english-coach/issues/101) 共用练习判分、回放或练习界面。后合入者在最新 dev 上重复此前已交付的首答、识别和重试用例。
- [#102](https://github.com/Zeming-Yuan/english-coach/issues/102) 与 [#107](https://github.com/Zeming-Yuan/english-coach/issues/107) 共用首页。[#103](https://github.com/Zeming-Yuan/english-coach/issues/103) 接课程导航时也须逐一整合改动到同一文件的票。[#105](https://github.com/Zeming-Yuan/english-coach/issues/105) 与 [#106](https://github.com/Zeming-Yuan/english-coach/issues/106) 对同一场景服务、页面、版本读取依次合入。
- 同一迁移头、恢复顺序和 V3 登记一次只整合一票。新表或字段在所属票内加法引入，同时验证旧备份及新数据往返；退回新写入口后，继续保留已交付数据的读取与恢复。此次拆分没有需要提前移除旧接口的全库重构。
- 每票在实施分支从最新远端基线复现红测，再运行该票列出的 HTTP 与真实浏览器验收。核对教学材料的关系、义项、题目唯一答案和场景表达由内容负责人完成。

## 已核实的起点

## 性能测量适用条件

这 12 票的验收目标是用户行为与数据正确性。如果实施中出现性能目标、要比较实现或配置，或需要用测量决定是否采用某种方案，应在修改前使用 `/benchmark-checklist`。先检查脚本计时区间、统计方法、错误数和输出正确性，再固定环境、负载、缓存、并发、样本与端到端指标。把实测基线、原始结果位置和复测命令写回该票计划，完成后按同样条件复测。仅有测量设计时，登记为“测量方案”，待有实测数据后再做性能判断。
