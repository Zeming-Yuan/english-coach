## 问题 / Problem Statement

学习者需要能够安装应用、完成每日学习、相信自己的进度，并在换设备或故障后恢复数据。当前版本已有词卡、FSRS 复习、拼写、听力选择、测验、混合练习、课程和故事，但以下问题妨碍这个目标：

1. **首次安装受阻。** 配置模板使用旧的 DeepSeek 变量，应用读取通用 LLM 变量；直接按模板配置会发生校验错误。空数据库执行迁移后缺少评分字段，真实首页请求失败。
2. **历史被当前状态覆盖。** 同一张卡每次复习更新原记录。实际复现中，跨三天提交的三次评分最终只有一条记录，历史、周统计和连续学习天数不能表达真实活动。
3. **备份恢复损失数据。** 导入用单词文本映射，合并同词的单词卡与句子卡；备份范围未覆盖全部数据库学习内容。非法字段还可能在旧进度被提交删除后才报错。
4. **界面完成与保存成功脱节。** 闪卡、听力和混合练习存在吞掉请求失败后继续推进的路径；拼写的判分和排期分两次写入，可能部分成功；混合选择题存在一次操作重复调用判分的路径。
5. **每日学习缺少明确主线。** 首页并列提供多种练习。相同表现因入口不同而对错词、排期、统计产生不同影响，用户难以理解每天应该做什么、完成后还需巩固什么。

评估时，提供测试用占位配置后，110 个后端测试通过，前端构建成功；真实首次启动仍失败。现有数据库测试直接按模型建表，未覆盖真实迁移链。测试通过不代表上述用户行为已经成立。

## 解决方案 / Solution

交付一个可信的每日学习版本：安装步骤可复现；每次学习确认保存后才推进；学习事件保留完整历史；备份能安全恢复；首页以“开始今天的学习”为主入口。

默认流程为：**到期复习 → 少量新词 → 针对本轮薄弱词的巩固 → 完成反馈**。专项练习保留在次级入口。约 10 分钟是体验目标，不是强制倒计时或完成门槛。

按依赖顺序交付：先修配置与迁移，再实现统一学习写入和统计，随后完成备份恢复，最后接通每日流程。整个规格的验收包含全部阶段，单独修复启动不能算本规格完成。

## 用户故事 / User Stories

1. 作为首次安装的学习者，我希望按照 README 和配置模板启动应用，以便无需猜测环境变量。
2. 作为尚未配置 AI 的学习者，我希望仍能打开应用、学习已有内容和恢复备份，以便模型配置不阻断本地功能。
3. 作为首次使用的学习者，我希望有一小组可直接体验的入门词卡，以便不用等待 AI 就能完成第一次学习。
4. 作为已有数据的学习者，我希望升级保留词库和排期，以便继续原有学习进度。
5. 作为使用自定义数据位置的学习者，我希望迁移和应用使用同一个数据库，以便初始化不会落到错误位置。
6. 作为学习者，我希望首页明确告诉我今天要学什么，以便不必先在多种模式间选择。
7. 作为学习者，我希望到期词优先进入每日流程，以便先完成复习责任。
8. 作为学习者，我希望新词量与复习负担分别表达，以便不会把每日目标误认为必须新增的词数。
9. 作为学习者，我希望提交评分后收到保存确认，以便相信“已完成”的含义。
10. 作为遇到网络或数据库故障的学习者，我希望保留当前题和答案并能重试，以便不丢失本次操作。
11. 作为重复点击或重试的学习者，我希望同一次提交只记录一次，以便排期和统计不被重复改变。
12. 作为响应丢失后的学习者，我希望重试能够识别已保存的结果，以便不会再次推进同一张卡的 FSRS。
13. 作为拼写练习者，我希望一次提交同时完成判分、记录和必要的排期更新，以便不会出现半成功。
14. 作为听力、测验或混合练习者，我希望得到一致且可解释的记录规则，以便知道哪些练习会影响排期。
15. 作为使用提示的学习者，我希望提示状态被记录，以便辅助下答对不会被显示成独立掌握。
16. 作为跳过题目的学习者，我希望跳过与答错、未作答分别记录，以便反馈如实反映表现。
17. 作为连续学习的学习者，我希望再次复习同一卡片不会抹掉昨天的活动，以便连续天数和热力图可信。
18. 作为查看统计的学习者，我希望区分完成词数、练习次数和正确率，以便理解自己的实际进展。
19. 作为老用户，我希望历史缺失时界面说明数据不完整，以便不会把推测当成真实成绩。
20. 作为每天学习的学习者，我希望统计按我的学习日计算，以便午夜附近不会错算日期。
21. 作为学习者，我希望完成页展示本轮薄弱词和后续复习，以便知道下一步是什么。
22. 作为备份用户，我希望通过界面导出全部数据库学习内容，以便换设备后可以继续学习。
23. 作为同时拥有单词卡和句子卡的学习者，我希望恢复后两者及各自进度保持独立，以便不会串卡。
24. 作为恢复备份的学习者，我希望在确认前看到影响范围，以便知道现有内容会如何变化。
25. 作为提供损坏或不兼容备份的学习者，我希望导入失败后原数据完整保留，以便可以安全重试。
26. 作为持有旧版备份的学习者，我希望能够恢复其中确实包含的内容，以便升级不会让旧备份失效。
27. 作为依赖语音或 AI 的学习者，我希望外部服务故障有明确提示且不破坏已保存进度，以便稍后继续。
28. 作为维护者，我希望真实安装和关键学习流程能自动验收，以便测试通过时能对实际使用建立信心。

## 最高测试 seam / Highest Test Seam

**已由用户确认：浏览器用户界面 → 真实 FastAPI → 通过 Alembic 迁移建立的隔离 SQLite。**

- 这是唯一的最高主验收 seam，测试从用户点击、输入、刷新、下载、选择备份文件等行为进入，观察界面和公开 HTTP 结果。
- 应用、路由、事务、FSRS 和数据库使用真实实现；主验收数据库不能通过直接按模型建表来替代迁移。
- 配置、数据库创建和应用启动是同一验收环境的准备步骤；另有从全新环境运行的安装检查，不能用预建数据库掩盖启动问题。
- AI 和语音是外部服务，使用可控替身覆盖成功、超时和错误；浏览器到应用的提交请求可注入断连、服务器错误和响应丢失。正常成功路径不伪造应用 API 响应。
- 沿用已有浏览器 E2E 入口和 HTTP 集成测试实践。HTTP 测试补充边界情况和定位故障，不把内部 ORM 写法或函数调用次数当成产品行为。
- 测试所需的时钟与外部服务配置从应用启动处注入；普通启动使用真实时间和正式适配器，不开放可供日常请求任意修改时间的接口。

## 实现决策 / Implementation Decisions

### 1. 模块与职责

- 保留现有前后端结构与本地数据库方案，不重写应用。
- 加深“学习提交”模块：现有评分入口成为适配器，通过同一模块完成判分、事件追加、必要的 FSRS 更新、错词更新和响应。
- “统计”模块读取学习事件，“备份恢复”模块负责格式、校验、映射与事务，“每日学习”模块负责编排有限队列；规则不再散布在各练习页面。
- 页面负责输入、待提交状态和结果展示；服务端是判分与持久化成功的权威来源。

### 2. 配置与首次启动

- README、模板和运行时统一使用 `LLM_API_KEY`、`LLM_BASE_URL`；模型路由与所选供应商保持一致。默认沿用当前实现的 MiMo 路由，不新增多供应商管理页面。
- 检测到旧 `DEEPSEEK_*` 配置时给出明确的迁移说明，不将旧密钥悄悄套用到不同供应商地址。新旧配置冲突必须说明冲突项，错误信息不输出密钥。
- 缺少 AI 密钥时允许应用和非 AI 功能运行；AI 生成请求返回可识别的未配置错误，界面指向配置说明。模型客户端按需初始化。
- 迁移与应用读取同一个 `DATABASE_URL`。数据库不可写、迁移版本不匹配等错误必须明确说明原因；不能仅显示永久加载状态。
- 提供显式“体验入门词卡”操作，加载随应用分发的 10 张已核对释义、例句与音标的词卡。只添加尚不存在的单词卡，重复操作不重复创建；不自动给老用户词库添加内容。

### 3. 迁移与旧数据

- 通过新增向前迁移修复缺失评分字段等实际结构差异；数据库已标记旧迁移完成但实际缺列时也必须能够升级。
- 完整验证从空库到最新版本，以及从代表性旧版本到最新版本的迁移。升级不得清空现有学习数据。
- 将“当前记忆状态”与“学习事件”分开存储：每张卡只有一个当前记忆状态，每次被接受的学习提交追加一个学习事件。
- 旧记录可能有同卡多行，使用最新有效复习时间、再按记录顺序确定当前状态；排期与累计次数保留来源。损坏且无法安全转换的数据使升级失败并说明原因，不能静默删除。
- 旧的累计次数、最后复习时间和最新评分属于迁移基线，不是完整事件历史。不能按累计次数伪造历史日期、补造过去答案或反推过去正确率。
- 保留可恢复的迁移前数据库副本；重复执行已完成的升级不改变业务数据。

### 4. 学习事件与原子提交

- 当前记忆状态保存 FSRS 状态、学习步骤、到期时间、稳定性、难度、最后排期时间及累计排期次数。
- 学习事件至少保存：事件标识、客户端提交标识、卡片标识、来源模式、题型、服务端接收时间、学习时区、用户答案或自评分、客观正误（可空）、是否跳过、提示类型、是否更新 FSRS、实际采用的评分，以及必要的排期前后摘要。
- 闪卡自评分和客观正误分列保存；“模糊/困难”不是客观选择题的错误答案。统计分别解释两者。
- 维持现有评分端点地址和既有成功响应字段；新增提交标识、来源和提示信息。所有本次交付的页面必须携带提交标识。
- 客观题由服务端根据卡片与可校验的题目上下文判分；听力提交不得仅相信客户端传入的正确选项下标，相关词题也不能误用原词作为标准答案。
- 同一次用户提交使用稳定的提交标识。首次提交在一个事务中追加事件、更新排期和错词权重；任何一步失败全部回滚。
- 同标识、同内容重试返回原提交结果，不再新增事件或改变排期；同标识、不同内容返回冲突错误。通过数据库唯一约束保障并发重试同样只生效一次。
- 既有无提交标识的调用可继续使用，但无法获得跨请求去重保证；浏览器验收及新版页面不得依赖这一兼容分支。批量判分为每个答案传递独立提交标识，整个批次校验后原子写入。
- 成功响应明确包含已保存结果。无效字段返回 422，卡片不存在返回 404，提交标识冲突返回 409；数据库故障返回通用失败信息并记录可定位日志，不返回已完成。

### 5. 不同练习的统一记录规则

| 行为 | 学习事件 | FSRS 更新 | 统计含义 |
| --- | --- | --- | --- |
| 闪卡，或课程/故事/详情中的显式记忆评分 | 一次自评事件 | 使用用户选择的 1–4 分 | 自评通过率，不冒充客观正确率 |
| 未提前显示答案、未使用提示或逐字正误反馈的拼写、填空 | 一次客观作答事件 | 答对用 3，答错用 1 | 独立提取结果 |
| 使用首字母、答案字母数或提交前逐字正误提示的拼写、填空 | 一次带提示事件 | 不更新 | 辅助练习结果 |
| 看中文选英文、听力四选一、相关词选择 | 一次客观选择事件 | 不更新 | 识别练习结果 |
| 用户显式跳过 | 一次跳过事件，正误为空 | 不更新 | 单独显示跳过数 |
| 仅打开、离开页面或播放发音 | 不产生作答事件 | 不更新 | 不计为完成 |

- 混合练习采用其具体题型的同一规则，不因外层模式改变含义。现有听力选择题更新 FSRS 的行为在本版本中明确调整。
- 页面提供“独立回忆”练习时，提交前关闭首字母、长度格子、逐字正误反馈及目标词朗读；若用户请求这些辅助，本题立即标记为带提示。
- 每次有效的客观作答只对错词权重加减一次；显式自评仍按现有低分强化、高分减权规则处理。跳过保留为本轮待巩固项，但不伪造一次客观答错。
- 自动判分的听力或选择请求不允许通过另传自评分来覆盖上述排期规则。旧响应中的毕业、下一次到期等字段表达真实当前状态，不暗示本题必然更新了排期。
- 选择题无法形成有效干扰项时，该题不作为客观选择题发出；词库很小时可以只完成闪卡与独立拼写，不阻断整轮学习。

### 6. 页面保存与异常路径

- 当前题采用可观察的“作答 → 保存中 → 已保存反馈 → 下一题/完成”状态。保存中防止重复提交；自动切题计时从保存成功后开始。
- 提交超时、断连或服务器错误时停留当前题，保留答案与提交标识，展示保存未确认及重试操作；不得增加完成数或进入完成页。
- 服务端已提交而响应丢失时，以原标识重试取得原结果；用户不能因为重试被重复排期。
- 新版页面不再分开发送“判分”和“更新 FSRS”两个业务写入。一个按钮也不能先调用判分、再通过反馈回调重复判分。
- 本地临时保存当前待确认提交，页面刷新后提示继续确认；不提供离线答题队列或后台自动重放。未确认提交不算完成。
- 题目所属卡片已删除时，明确告知无法保存；允许用户明确跳过失效题并重新加载队列，不显示该题已保存。
- AI 升级例句、故事生成或 TTS 失败不回滚已成功保存的学习结果。后台 AI 不能决定一次学习提交是否完成；失败有兜底或稍后重试入口。
- 空队列、加载失败和服务未配置必须使用不同状态；失败页有重试或返回入口，不能把错误解释成“今天没有内容”。

### 7. 统计、时区与自适应

- 新事件以 UTC 存储时间，按配置的学习时区归属学习日，默认 `Asia/Shanghai`。事件保存当时的学习时区，后续设置变化不重写历史日期。
- “今日完成词数”是当天有成功排期事件的不同卡片数；“练习次数”是当天保存的作答事件数，跳过单列。同卡同日多次真实作答增加练习次数，但不重复完成词数。
- 历史、热力图与连续学习天数从事件读取；同卡再次复习不能删除前一天活动。有至少一次非跳过作答的学习日算作连续学习的一天。
- 客观正确率只使用已判分的客观作答，提示练习与独立提取分别展示，跳过和未知结果排除分母；无有效样本显示“暂无数据”，不显示 0% 或 100%。闪卡另显示自评通过率。
- 自适应新词量基于近 7 个学习日内会更新 FSRS 的事件，1–2 分视为需要强化、3–4 分视为通过；同卡同日只取首次此类事件，避免即时重做拉高指标。界面称其为“复习通过率”。
- 沿用错误比例超过 30% 推荐 5 个、低于 15% 推荐 15 个、其余 10 个的产品规则；不足 20 个有效样本时不自动上调，默认 10 个，明显高错误比例仍可下调。该门槛是保守产品默认值。
- 最低每日目标与新词配额分开：提高完成目标不能抵消系统对新词量的下调。完成目标在一轮开始时确定，不因队列减少而缩小。
- 升级前不可还原的历史标为不完整，只展示有明确日期依据的最后活动基线；不用于正确率或自适应样本。累计次数可包含迁移基线，但要区别于已记录事件数。
- 毕业规则暂沿用现有业务判定，并让详情、统计和毕业行为读取同一规则；本规格不把毕业等同于已证实掌握，也不重新引入句子卡每日排期。

### 8. 完整备份与安全恢复

- 提供可从设置进入的“备份与恢复”界面，接通现有导出、导入能力；浏览器必须能完成下载备份、选择文件、预览、确认及结果反馈。
- 新格式带版本号、实际导出时间与学习时区。范围为数据库内的全部词卡字段、当前记忆状态、学习事件、迁移基线、记忆法、错词、困难词标记、课程、故事及其词卡关联。
- API 密钥、环境配置、语音缓存及仅存在浏览器中的外观/播放偏好不包含在数据库备份中；界面明确范围，不能宣称这些也会恢复。
- 通过备份内实体标识建立旧 ID 到目标 ID 的映射；关系不能只按单词文本恢复。同词的单词卡和句子卡保持独立，嵌套关联与提交去重标识随数据恢复；幂等结果中引用的实体 ID 也必须映射到恢复后的实体。
- 新版备份采用明确的全量恢复语义：确认成功后，数据库学习内容与备份在逻辑上等价，目标数据库中备份未包含的学习内容会被替换。界面预览数量与替换影响，用户确认前不修改数据库。
- 恢复前保存当前数据的可用备份，并在界面给出位置或下载方式；备份保存失败就不执行替换。本版本不自动删除历史备份。
- 先完整校验版本、必填字段、类型、时间、FSRS 枚举及数值范围、标识唯一性和所有关联，再在单一事务中替换数据。无效数据返回结构化 422，指出集合和记录；不边删除边校验、不静默跳过损坏记录。
- 写入中发生异常时整体回滚，原数据和关联保持完整；服务端返回失败后也不能残留已清空的复习、记忆法或错词。学习写入与恢复写入串行执行，恢复结果页只在事务提交后出现。
- 无版本号的旧备份按兼容导入处理：只恢复实际包含的字段与关联卡片，不清空其他未包含的学习内容；预览明确“旧版部分恢复”。旧备份缺少的故事、课程等不能补造。
- 旧版先按备份卡片 ID 区分卡型，再对目标使用单词与卡型匹配；无法消歧的多条匹配拒绝导入并提示原因。旧复习作为当前状态和不完整历史基线恢复，不伪造事件。
- 重复导入同一旧备份不重复创建卡片或关联；重复全量恢复同一新备份保持逻辑等价。空备份也必须经过明确影响预览和确认；带悬空关联的“空词库”备份拒绝导入。
- 新版导出时间有效；往返比较排除导出时间、数据库内部 ID 等非业务差异，业务字段、排期和关联必须一致。

### 9. 每日学习流程

- 首页只突出一个学习主按钮；专项拼写、听力、测验、混合练习收纳到次级入口，保留现有功能。
- 每轮开始获取去重队列与固定目标：到期单词卡优先，同组内错词和困难词优先；单轮最多 20 张到期复习，剩余到期数量可见并可开始下一轮。随后加入自适应配额内的新词。
- 已在本轮完成的卡不因同时属于新词、到期、错词或困难词而重复进入主队列。用户另选专项练习产生的新作答是独立事件。
- 主队列结束后，为本轮答错、低分或跳过的词提供最多 3 道巩固题；可明确跳过该阶段。巩固产生独立带来源事件，遵循同一提示与排期规则。
- 完成页以已保存数据展示完成词数、独立提取/辅助练习结果、跳过项、仍需巩固的词，以及已有排期支持的下一步。不承诺“明天一定不会忘”。
- 全部到期词已完成但还有专项练习时，首页明确区分“今日复习已完成”与“可以继续练习”；所有内容为空时进入入门词卡、加词或恢复备份引导。
- 课程与故事继续作为补充入口，不把“生成课程”作为新的每日完成证据。

## 测试决策 / Testing Decisions

### 测试标准与既有实践

- 好的测试验证用户可观察行为、公开契约与数据保存的结果，不绑定内部函数名、组件层次或 SQL 语句写法。
- 复用现有浏览器学习流程、HTTP TestClient 和隔离数据库实践；主验收与迁移集成测试都执行真实迁移。原有按模型建表的快速测试可保留，但不作为安装或升级正确的证据。
- 覆盖配置与启动、学习提交、统计、备份恢复、每日流程这五组模块，经已确认的最高 seam 运行代表性完整路径；复杂输入组合由现有 HTTP seam 补充。
- 测试固定时钟、时区、题目数据和必要的随机来源；FSRS 检查合法状态变化及重试不变化，不依赖生产随机扰动下的某个精确间隔。
- 外部替身必须接到应用的外部服务适配处；普通端到端成功场景的学习写入和读取经过真实后端。
- 使用本次运行独有的数据库、端口、下载目录和浏览器上下文；不接触用户数据库，不调用真实付费 AI。
- 必经步骤不可因队列为空、AI 超时或入口缺失而静默跳过。断言失败、未处理错误或流程中断必须使命令以非零状态退出，并保留诊断信息。
- 浏览器至少覆盖 420×880 的触屏布局和 1280×720 的桌面布局；主流程控件可用键盘操作，保存状态和错误有可感知文本，不能只靠颜色或音效。

### 可运行的测试入口

- 实现后提供 `npm --prefix frontend run test:e2e` 作为主验收命令，复用现有浏览器脚本的交互实践；该命令在本规格编写时尚不存在，属于交付要求。
- 主验收命令负责准备隔离目录和数据库、执行迁移、启动带可控外部服务的应用、运行浏览器断言，并在结束时关闭测试进程。浏览器依赖安装方式写入开发说明，不依赖用户电脑已装特定 Edge 浏览器或已启动正式实例。
- 后端补充回归入口为 `python -m pytest`，测试必须自带占位配置和外部替身，不要求提供真实密钥。
- 前端构建入口为 `npm --prefix frontend run build`。主验收使用本次构建产物，不仅检查仓库中已有静态文件能够返回 200。
- 验收输出按 T01–T21 标识场景并汇总成功、失败和阻塞；阻塞项也使整体验收失败，不能按通过处理。

### 关键验收场景

| 编号 | 场景与故障注入 | 观察与断言 |
| --- | --- | --- |
| T01 | 全新目录、模板配置、空 SQLite，执行迁移并启动 | 真实首页可用；无密钥时非 AI 功能可用，AI 操作明确提示未配置 |
| T02 | 自定义数据库地址、旧配置名称、配置冲突 | 应用与迁移使用同一目标；旧名称有迁移说明，冲突不泄露密钥 |
| T03 | 旧版本数据库升级，包含迁移已标记完成但缺评分字段的情况 | 数据及排期保留；能升级至一致结构并提交一次学习；再次升级不改变数据 |
| T04 | 浏览器加载入门词卡两次，完成第一次学习 | 不依赖 AI；同词同卡型不重复；主流程可完成并保存 |
| T05 | 保存前断连、服务器错误、数据库写入失败 | 当前题和答案保留；事件、排期、错词全部不变；不增加完成数 |
| T06 | 服务端提交成功但响应丢失，刷新后用原标识重试 | 原结果可取回；恰好一条事件，排期和错词只改变一次 |
| T07 | 连点、并发重试、同标识改答案、批次含无效项 | 同提交只生效一次；冲突返回 409；无效批次不部分落库 |
| T08 | 同一张卡在连续三天分别评分 1、3、4 | 三次事件和三个学习日均保留；复习通过率为 2/3，而非只保留最后一次的 100% |
| T09 | 同日两次真实评分，加上一次请求重试 | 两次事件、一个完成词；重试不增加任何计数 |
| T10 | 在独立与混合入口分别提交同类题 | 判分、提示分类、错词和排期效果一致；一次选择不被记录两次 |
| T11 | 独立拼写、打开提示、四选一、跳过、仅离开 | 分别符合记录规则表；客观正确率分母和 FSRS 变化正确 |
| T12 | 上海时间午夜前后作答，系统 UTC 日期不同 | 学习日、热力图、连续天数按规定时区一致归属；旧活动不随再次作答消失 |
| T13 | 只有旧累计记录，或样本不足、无客观判分样本 | 显示历史不完整和暂无数据；未知记录不提高正确率或新词推荐 |
| T14 | 含同词不同卡型、所有卡字段及全部关联的新版备份，经界面导出并恢复到另一迁移数据库 | 词卡、排期、事件、记忆法、困难词、课程、故事及关联逻辑等价，且不串卡 |
| T15 | 导入非法 state、数值、日期、重复 ID、悬空关联或未知版本 | 明确拒绝并指出记录；原数据库学习内容完全不变 |
| T16 | 通过预校验后注入写入中途故障；另测预恢复备份写入失败 | 不留下部分替换；原内容可继续学习，不显示恢复成功 |
| T17 | 导入旧版部分备份两次，包含同词两种卡型；另测无法消歧的旧数据 | 可确定的内容恢复且不重复，不擦除未覆盖内容；歧义数据安全拒绝 |
| T18 | 20 张以上到期词、少量新词、同卡多种优先标记 | 主队列去重并按优先级排列；剩余到期数可见；目标不随进度缩小 |
| T19 | 本轮答错和跳过，进入巩固；另测零薄弱词与词库过小 | 最多 3 题，记录含来源；可跳过；没有可生成题时仍正常结束 |
| T20 | TTS 失败、AI 未配置或超时、页面初始加载失败 | 说明真实原因并可恢复；已提交学习不回滚；不把失败显示为空队列 |
| T21 | 在两种视口用键盘完成学习及备份预览/取消 | 控件可达、状态明确；取消不写入；布局不遮挡保存、重试和确认操作 |

## 明确不做 / Out of Scope

- 不新增云同步、多账号、账号系统、公开托管部署、支付或商业化设施。
- 不重写前后端框架、不切换数据库、不全面视觉重设计、不建立新的通用业务框架。
- 不重新设计 20 级课程体系，不在本次修订课程“生成/完成”的完整状态模型；课程仅接入统一学习提交。
- 不改造为口语评分、自由对话老师或新的学习模式；不重新启用句子卡每日复习。
- 不承诺任何学习效果百分比；不在本版训练个性化 FSRS 参数或开展学习科学实验。
- 不从现有当前状态重建已经丢失的完整历史，不把缺失评分填成正确。
- 不提供任意两个词库的交互式冲突合并工具，不支持未知未来备份版本。
- 不把密钥、缓存或浏览器偏好纳入数据库备份，不提供自动删除旧备份的保留策略。
- 不提供离线答题自动同步、跨设备未提交题续接或多人并发协作；单机重复点击与重试去重仍在范围内。
- 不将修复本规格所有问题扩大为全仓库格式化、全依赖升级或完整无障碍合规认证。
- 本规格编写不实施产品修复，不创建外部 issue、评论、标签或 PR；外部发布需要另行授权。

## 假设 / Assumptions

以下是无需重新访谈即可实施的默认值。改变它们应更新本规格和相应验收，而不能在实现中静默选择另一套行为。

1. 分享方式是每人独立运行自己的本地实例，不是多人共享一个无隔离数据库。
2. 继续使用 FastAPI、React、SQLite、Alembic 和 FSRS；AI 默认保留当前 MiMo 配置方向。
3. 学习时区默认上海；所有基于“今天”的用户显示遵循这一约定。
4. 独立提取与识别练习采用本规格规则表；这是一致性与解释性的产品选择，不宣称选择题没有学习价值。
5. 入门包为 10 张经内容核对的词卡；巩固上限 3 题，到期复习单轮上限 20 张，自适应上调门槛 20 个有效样本。它们是可调整的产品默认值。
6. 新版备份是数据库全量恢复，旧备份是明确标注的兼容部分恢复；都必须先预览并由用户确认执行。
7. 历史缺失采取诚实标注；不能以“看起来完整”为理由伪造日期或提高历史统计。
8. 接受对旧练习排期语义的明确修正；保留端点及成功响应兼容面，不为未升级的旧页面承诺幂等保证。
