## 问题 / Problem Statement

学习者需要知道自己是否真正记住、今天应该练什么，以及学过的英语能否用于简单生活情境。项目已具备每日主队列、FSRS、独立拼写、识别练习、提示记录、只追加学习事件、有限巩固、统计与完整备份，但以下差距限制了这个目标：

1. **掌握表达高于证据。** 现有毕业条件是进入指定 FSRS 状态或累计复习至少三次；答错同样可能增加累计次数。详情页把毕业直接表示为 100% 掌握，用户可能将学习阶段变化理解为稳定记忆。
2. **课程生成被显示为课程完成。** 现有课程级别随生成递进，页面用已生成课数展示已完成课数，课程推进没有独立提取检查。单词的“记住了”操作是自评，不能证明课后能够独立作答。
3. **故事难度缺少个人依据。** 当前默认从没有复习记录的词中选最多八个，生成约一百词的故事。提示词要求“适合零基础”，但没有按用户词汇证据校验内容难度，读后也缺少理解和提取检查。
4. **统计与补救动作脱节。** 现有指标已区分独立提取、辅助、识别、自评，却缺少按实际间隔解释的延迟回测，以及由薄弱项直接进入匹配练习的路径。
5. **每日计划缺少时间约束。** 当前区分最低完成目标、新词建议与本轮卡数，但用户不能按此刻可用时间选择有限计划。中断数日后的积压也缺少明确的恢复学习选项。
6. **词汇练习到实际应用之间缺少验证。** 当前语音主要用于播放，课程、故事和拼写未组成有边界的交互场景。用户难以判断能否用已学表达完成一个具体任务。

以上为代码与文档可支持的产品差距，尚无真实用户实验能证明某项优化带来的提升幅度。本规格规定可实现、可验收的行为；学习收益通过后续小范围使用观察。

## 解决方案 / Solution

交付一套以真实学习证据驱动的个人训练流程：用户看到有依据的能力状态，完成短课程与检查，阅读难度受控的故事，得到能直接执行的练习建议，按可用时间进行每日学习，并用已学内容完成简短文字场景。

| 单元 | 本次交付内容 | 用户能够获得的结果 | 依赖 |
| --- | --- | --- | --- |
| F1 掌握与毕业定义 | 学习证据、当前有效状态、历史依据与练习解锁分开表达 | 理解哪些能力经过何种验证 | 全局事件与内容修订规则 |
| F2 课程学习闭环 | 本课目标、浏览记录、课后短测、薄弱项与延迟回测入口 | 看完课程后知道哪些还需巩固 | F1；F4 提供延迟回测 |
| F3 个性化故事 | 词汇与长度约束、简化版本、读后理解及提取题 | 阅读材料可理解，读后能检查效果 | F1、F4、生成校验 |
| F4 统计与下一步建议 | 分类表现、延迟回测、解释及指定词练习入口 | 看到结果后能直接采取行动 | F1；为 F2/F3/F6 提供共用练习上下文 |
| F5 按时间安排每日学习 | 3/8/15 分钟预览、有限词卡计划、暂停继续和恢复模式 | 用当前可用时间完成合适的一段学习 | F1、现有每日队列和新词配额 |
| F6 AI 场景练习 | 三类场景、三轮文字任务、受约束的反馈与应用证据 | 知道能否在指定情境表达目标意思 | F1、F4、生成校验 |

建议交付顺序：第一阶段 F1/F2/F4；第二阶段 F3/F5；第三阶段 F6。基础事件、内容修订、备份兼容随最先引入它们的单元交付。不能把后续单元移入“明确不做”来宣称本规格完成。

## 用户故事 / User Stories

1. 作为零基础学习者，我希望词卡状态说明用了什么证据，以便理解进展的含义。
2. 作为反复答错的学习者，我希望复习次数增加不会使词卡显示为已掌握，以便得到诚实反馈。
3. 作为使用提示的学习者，我希望提示下的正确单列，以便知道是否还需独立练习。
4. 作为通过选择题的学习者，我希望识别能力与独立回忆分别展示，以便避免误判能力。
5. 作为使用闪卡自评的学习者，我希望自己的评分被保存并正确标注，以便保留原有学习方式。
6. 作为解锁句子练习的学习者，我希望知道解锁表示可尝试拓展，以便合理理解“毕业”。
7. 作为有历史数据的学习者，我希望缺少可靠依据时看到说明，以便不会把推测当作事实。
8. 作为曾经答对又再次遗忘的学习者，我希望当前状态反映最近表现，以便及时补强。
9. 作为长期未练某词的学习者，我希望看到证据日期和待复测提示，以便判断它是否仍然可靠。
10. 作为编辑词卡的学习者，我希望修改后的内容重新积累适用证据，以便旧题结果不会证明新内容。
11. 作为课程学习者，我希望开课时知道本课能练会什么，以便带着明确目标学习。
12. 作为只生成了课程的学习者，我希望课程显示为待学习，以便准确了解进度。
13. 作为看完课程的学习者，我希望明确标记已浏览，以便记录自己实际完成的步骤。
14. 作为完成课程内容的学习者，我希望做少量无提示题，以便检查是否能够独立回忆。
15. 作为短测答错的学习者，我希望得到答案和待巩固项，以便知道下一步练什么。
16. 作为暂时不想测验的学习者，我希望能继续下一课并保留待测标记，以便自主安排学习。
17. 作为重复练习同一课的学习者，我希望即时重试与首次结果分别解释，以便不高估记忆保持。
18. 作为数日后复习课程的学习者，我希望能进入延迟回测，以便检查内容是否留得住。
19. 作为打开旧课程的学习者，我希望缺少目标或题目时仍能阅读，以便继续利用已有材料。
20. 作为阅读故事的学习者，我希望材料主要复用已有学习依据的词，以便能够读下来。
21. 作为刚开始学习的用户，我希望词汇不足时有明确的入门材料入口，以便不会被高难度故事阻断。
22. 作为感觉故事太难的学习者，我希望获得一个更短、更简单的版本，以便继续练习。
23. 作为读完故事的学习者，我希望回答少量理解与回忆题，以便知道自己是否理解和记住。
24. 作为借助原文答题的学习者，我希望结果注明使用过原文，以便与独立提取区分。
25. 作为阅读旧故事的学习者，我希望原文仍能打开，以便新规则不会使已有内容失效。
26. 作为遇到生成失败的学习者，我希望已有故事和进度保留，以便稍后重试。
27. 作为查看统计的学习者，我希望每个比例都有样本数，以便知道结果有多充分。
28. 作为尚无有效样本的学习者，我希望看到暂无数据，以便不会误读为零分或满分。
29. 作为完成数日前学习的用户，我希望检查隔日及一周后的回忆，以便了解保持情况。
30. 作为期间再次看过答案的学习者，我希望回测按实际记录间隔解释，以便不把重新学习后的答对计作长间隔保持。
31. 作为连续重做某题的学习者，我希望回测统计不会被同日重试抬高，以便看到真实首答表现。
32. 作为有薄弱词的学习者，我希望从统计直接进入对应词和题型，以便减少选择练习的成本。
33. 作为收到建议的学习者，我希望看到建议依据，以便理解系统为什么这样安排。
34. 作为样本不足的学习者，我希望建议说明依据有限，以便不会把它当作确定诊断。
35. 作为只有几分钟的学习者，我希望选择可用时间并预览题量，以便决定是否开始。
36. 作为有到期复习的学习者，我希望有限计划优先安排到期词，以便控制复习积压。
37. 作为复习负担较大的学习者，我希望系统减少或暂不安排新词，以便维持合适负担。
38. 作为学习速度变化的用户，我希望预计耗时逐渐参考自己的记录，以便计划更贴近实际。
39. 作为临时需要离开的学习者，我希望能在保存后暂停，以便保留当前进展。
40. 作为刷新页面的学习者，我希望恢复同一轮和未确认提交，以便不重复评分。
41. 作为中断数日后回来的学习者，我希望获得有限的恢复计划，以便容易重新开始。
42. 作为超出预计耗时的学习者，我希望自行选择暂停或继续，以便保有控制权。
43. 作为学习简单生活英语的用户，我希望选择买饮品、自我介绍或问路场景，以便练习实际表达。
44. 作为进入场景的学习者，我希望先看到目标和所需词汇准备情况，以便选择适合自己的任务。
45. 作为场景练习者，我希望通过短文字对话完成任务，以便尝试独立组织表达。
46. 作为请求场景提示的学习者，我希望帮助被记录，以便完成后知道哪些表达仍需要辅助。
47. 作为使用合理但系统无法判断的表达的学习者，我希望结果显示未判定，以便不会被武断判错。
48. 作为完成场景的学习者，我希望区分完成流程与独立通过，以便准确理解应用能力。
49. 作为收到纠正的学习者，我希望每轮只处理一个关键问题，以便能够理解并改进。
50. 作为重复场景练习的学习者，我希望历史尝试和本次结果都能查看，以便观察变化。
51. 作为遇到 AI 或语音故障的学习者，我希望已提交的答案仍被保存，以便不会丢失学习结果。
52. 作为遇到保存失败的学习者，我希望保留答案并能确认同一提交，以便安全恢复。
53. 作为在多个页面学习的用户，我希望旧页面结果不会覆盖新内容，以便保持状态一致。
54. 作为更换设备的学习者，我希望新增的课程、回测和场景记录随备份恢复，以便继续学习。
55. 作为恢复旧备份的学习者，我希望知道其中缺少哪些新记录，以便在确认替换前了解影响。
56. 作为小范围试用的维护者，我希望有稳定的用户级验收入口，以便复现行为并判断是否交付。
57. 作为评估学习效果的维护者，我希望区分练习内表现、延迟结果和任务结果，以便避免混用指标。
58. 作为个人用户，我希望所有能力判断都能在本地记录中找到依据，以便核对推荐与状态。

## 最高测试 seam / Highest Test Seam

**已确认：浏览器用户操作 → 真实前端 → 真实 FastAPI → 真实 FSRS、事务 → 经 Alembic 迁移建立的隔离 SQLite。**

- 六项共用这个唯一主验收 seam，从点击、输入、提示、跳过、暂停、刷新、下载和文件恢复进入。
- 主断言是可见状态、公开 HTTP 结果及完整备份可以核对的持久化结果。不会通过 mock 掉正常应用 API、替换 FSRS 或直接按模型建表来证明产品通过。
- 外部 AI 和语音提供方使用可控替身，覆盖成功、超时、无效内容及失败。实际模型内容质量另做明确的人工样本评估。
- 复用应用启动时注入的时钟，覆盖 24 小时、七天、午夜和时区边界；不开放生产调时接口，不实际等待数日。
- 复用已有提交故障注入、网络断连和响应丢失设施，检查保存确认和幂等回放。
- 公开 HTTP、迁移与进程测试是此真实应用边界的补充，用于高组合数、不适合全部通过点击复现的条件；不是另一套业务规则。
- 在桌面与移动两个现有视口运行。同一用户行为按两种视口验收，浏览器完成不能替代真实迁移及恢复演练。

## 实现决策 / Implementation Decisions

### 1. 全局模块与证据规则

1. 保留本地运行、React/FastAPI、SQLite 和现有 FSRS 调度方式。加深现有学习提交、统计、课程、故事、每日编排与生成模块的职责，不引入独立的第二套记忆调度器。
2. 已接受作答继续由统一学习提交模块拥有写事务：判分、事件追加、需要时更新 FSRS、错词变更和练习题结果关联一起提交。提交标识、指纹和缓存响应继续负责幂等回放。
3. 练习轮次负责目标、题目快照与流程，不自行写一份独立正误历史。卡片输入或识别题的结果关联真实学习事件；场景任务的整体应用结果单列为任务证据。
4. 增加共用的持久化练习上下文，支持课后短测、故事检查、延迟回测、指定词练习和场景练习。保存用途、内容修订、冻结题目、提示、题目处理结果、来源及必要的恢复信息；不把每一种流程做成互不关联的成绩系统。
5. 每个题目有稳定身份和服务端认可的判分上下文。浏览器不能提交自造的正确答案、题目选项或延迟间隔作为权威结果。
6. 内容增加可核对的修订身份。词形、释义、题目语义、故事版本或场景规则实质变化时产生新修订；旧结果保留为历史，不自动证明新修订。仅修改排版或用户记忆法不使词义证据失效。
7. 提交依据创建题目时的修订。关联内容已变化时返回 409，提示重新加载；内容已删除时返回 404。发生冲突不增加事件、进度或排期。
8. 已保存提交的同内容回放优先于题目失效检查。缓存结果如实表达原提交时的事实，后续重新读取展示当前状态；回放不会让旧证据重新变成新证据。
9. 阅读、答案显示与发音播放可产生“内容接触记录”，用于解释回测间隔。它们不是作答，不计每日完成、正确率、连续学习日或 FSRS。
10. 内容接触只记录应用内实际展示/播放并得到记录确认的目标内容、修订、来源和服务端时间；不声称知道用户在应用外的学习。仅在接口中预取、未展示的内容不算已接触。
11. 接触上报先保存本地待确认标记，得到服务端确认后再清理。失败时保留学习功能，并把相关回测标记为间隔依据不完整；刷新后仍需确认。存储不可用时不能宣称已完整记录该段接触。延迟确认使用服务端确认时间作为保守依据，不采信客户端回填的更早日期来制造长间隔。
12. 提示一旦使用，本题持续属于辅助作答。关闭提示、切换视图或刷新不恢复成本题独立作答；展示标准表达、目标词音频和带答案原文均按适用题目记录辅助。
13. 自评、独立提取、辅助、识别、跳过沿用各自的已存事件含义；后台 AI 任务只处理内容，不产生记忆评分。

### 2. F1：能力状态与练习解锁

1. 现有毕业字段继续作为兼容的句子练习解锁判断，用户界面统一称“已解锁句子练习”。累计次数门槛可以解锁拓展，不再被展示为 100% 掌握。
2. 新增由服务端生成的学习证据摘要，独立于现有毕业布尔值，包含证据类别、当前有效性、样本数、最近证据时间、适用修订、薄弱/待复测标记及原因。首页、词卡详情、词表、统计和分享图使用一致解释。
3. 能力维度并列展示，不强制推断线性等级：已接触、独立回忆已有证据、长间隔保持已有证据、指定语境应用已有证据。没有口语检测时不出现“口语已掌握”。
4. “独立回忆已有证据”的默认门槛：当前修订下，最近一次独立提取失败之后，至少两个不同学习日的首答独立输入正确，且两次正确至少相隔 24 小时。只有一条时显示“独立答对 1 次，仍需验证”。
5. 辅助答对、识别答对、自评高分、同日重试及迁移基线不能满足上述门槛。存在即时成功记录时可以展示该事实，但不能提升为跨日回忆证据。
6. “长间隔保持已有证据”需有 F4 定义的有效一周回测独立正确；“指定语境应用已有证据”需有 F6 的规则判定、无提示、对应目标的有效结果。应用证据不推导未测的单词或其他场景能力。
7. 最新独立输入答错会使当前回忆/保持标记转为待巩固；旧成功仍可查看。场景失败仅影响相应场景应用标记，不自动否定所有词汇维度。
8. 当前有效证据超过 30 天未得到同维度有效验证时，展示历史证据及“待复测”，不自动制造一次失败。FSRS 到期时间继续独立展示。
9. 缺少修订或来源证据的旧数据标注依据不足。升级保留原始记录及历史正确事实，不按累计次数回填跨日成功、接触时间或应用能力。
10. 移除按复习次数换算的“掌握百分比”。可展示真实计数、日期和判定条件，不把启发式规则包装为记忆概率。

### 3. F2：课程目标、短测与完成含义

1. 保留现有二十级课程内容结构。每课增加一个可观察的简单目标，如“能用本课表达说明自己想要的物品”；没有应用验证时，课后词汇检查只能证明本课所测词汇表现。
2. 课程生成、浏览、短测和延迟回测分别记录。新生成课程为待学习；用户明确选择“内容已看完”后标记已浏览；仅打开或生成课程不记录浏览完成，也不产生作答。
3. 已有旧课程保留可读，标为“已有内容，学习状态未记录”。目标可从主题的随应用分发说明补齐；不凭旧课程级别伪造完成记录。
4. 每课默认三道中文释义到英文的无提示输入题，优先覆盖本课尚无回忆证据的不同词。有效词少于三个则按实际数量出题，并说明覆盖范围；一个有效词也可练，没有有效题时说明原因并允许返回内容页。
5. 测试界面隐藏词表、标准答案、目标词朗读、长度和逐字反馈。请求这些帮助后按辅助记录；回看有答案的课程内容同样使当前未提交题成为辅助作答。
6. 一轮短测全部题目无提示独立正确时标为“短测通过”；其他完整作答结果为“待巩固”，用户跳过整轮为“未完成短测”。不足三题通过时显示实际题数，不暗示检查了整课所有能力。
7. 失败后可以只练薄弱词，或重新开始一轮检查。原轮次首次结果保留，重试结果另列；当天重做不能计作跨日保持。
8. 词汇短测复用独立输入的既有排期规则。单次输入的 FSRS 更新仅一次，课程总结果不额外评分、不重复记每日完成。
9. 用户可以选择“稍后检查，继续下一课”。界面保留当前课待测状态，课程列表区分已生成课数、已浏览课数、短测通过课数。
10. 二十课均短测通过才可显示“20 课短测全部通过”，不显示笼统的英语等级达成。延迟回测状态另列，不因即时短测全部通过而自动通过。
11. 原有下一生成级别与兼容字段继续表达生成进度；新版页面读取新增的学习进度字段，不能再用生成字段显示已学完。生成上限提示改为课程已全部生成、可继续学习与检查。
12. 新课程生成结果先校验目标、唯一词形、必要释义、例句/翻译和对话中英配对，完整有效后再原子保存课程与新增词卡。校验或保存失败不留下半课或重复加词，不消耗课程级别。

### 4. F3：可检查的故事难度与读后闭环

1. 生成时以 F1 的有效回忆证据挑选复用词，结合随应用分发且有版本的基础支撑词表。支撑词是允许出现的教学材料，不标成用户已经掌握。
2. 默认故事选择一至三个已有回忆依据的目标词，可另外引入零至一个用户明确同意的新目标词。不再强制需要至少三个未复习新词才能开始。
3. 默认故事为 40–70 个英文词，每句最多 12 个词；“更简单”生成一个 20–40 词、每句最多 8 词的独立版本。两种模式都最多允许两个不同的未覆盖词形，且所有目标词必须实际出现。
4. 覆盖校验使用可复现的词形规则：英文词统一大小写，词内撇号保留；仅认可明确列入支撑表的词形变化。没有显式映射的复数、时态和缩写不自动算作已知。词形覆盖及句长检查覆盖给用户阅读的英文标题、正文、题干和选项；总词数限制针对正文。报告称“词形覆盖检查”，不推断用户一定理解全文。
5. 生成输出同时提供逐句翻译、实际目标词和一题可从原文定位答案的三选一理解题。题目需有明确证据句、唯一选项和答案上下文，未达到结构和引用检查则不能成为可发布练习。
6. 生成后由服务端校验长度、句长、覆盖词、目标词出现及中英配对。最多自动修正重试一次；仍无效时说明失败，保留旧内容并提供重新生成或入门材料入口。
7. 词汇依据不足时提供已核对的短入门材料，或解释缺少适合材料的原因；不悄悄扩大未知词数量，也不以自评高分补齐“已知词”。新词明确显示，是否加入词库由用户选择。
8. “更简单”保留原故事，新版本与原版本分别有身份和结果。后台晚到的结果不能替换当前已选择版本。
9. 读后默认最多两题：一题理解选择、一题目标词独立提取。理解题可回看原文，记录是否回看；结果归入阅读识别。提取题默认隐藏目标词和原文，若查看原文或提示则归入辅助。
10. 理解选择不更新 FSRS；独立词汇输入按既有规则排期；辅助输入不排期。紧接阅读后的答对不计作延迟保持。
11. 故事读完、理解题作答和目标词回忆分别展示，不用故事阅读次数替代课程或每日词卡完成量。
12. 旧故事可以继续阅读，缺少可校验题目时显示“本篇暂无检查题”。不在无明确操作时用 AI 重写旧故事或补造阅读成绩。

### 5. F4：延迟回测与可执行建议

1. 保留独立提取、辅助、识别、自评指标和现有新词建议口径。新增隔日回测、一周回测和场景任务结果，分别展示，不合成一个总正确率。
2. 延迟回测默认是有限的中文释义到英文输入，每轮最多三道不同词题；不依赖实时 AI。候选必须有可定位的既有学习依据、当前内容修订及足够完整的应用内接触记录。
3. “间隔”是题目发出前最后一次已记录的相关作答或答案接触，到本次实际作答的 UTC 时长。标签说明“距应用内上次记录”，不声称用户期间完全没有接触该词。
4. 相关接触包括该目标词/目标答案在词卡、词表、课程、故事、提示或标准发音中的实际呈现，以及其他已保存非跳过作答。单纯预取和当前题无答案的中文提示不算答案接触。
5. 隔日窗口为至少 24 小时且不足 72 小时；一周窗口为至少七天且不足十四天。超出窗口的结果显示实际间隔并进入“其他间隔”，不挪入命名窗口。
6. 发题时冻结间隔依据。提交前若另一页面产生新的相关接触，服务端以最新依据重新分类；不足窗口则仍保存真实作答，但显示为普通/辅助练习，不进入原窗口分母。当前题作答后显示答案不反过来取消这次已经成立的回测资格。
7. 候选取符合窗口且尚未在当前学习日完成该类首测的词，优先到期/薄弱项，再按较早的最后接触时间和稳定身份排序。测试不为取得样本而推迟已有复习；没有合适候选时显示空态及普通练习入口。
8. 每词、每学习日、每个窗口只取第一道该类回测的处理结果：独立正确计成功，独立错误计失败；请求提示或跳过则分别计辅助/跳过，不进入独立正确率。当天后续重做不能替换首测结果或补进独立分母。
9. 统计同时展示成功数/独立有效样本数、实际间隔、辅助数、跳过数和覆盖词数。有效样本为零时显示暂无数据；不足十个独立样本时标注样本较少，不输出确定的能力诊断。
10. 缺少足够接触依据的旧数据可以进行普通独立练习并建立新的时间依据，但不能直接标记为隔日或一周回测。
11. 独立回测仍复用既有输入题排期规则，不再追加第二次自评。用户在回测前进行了正常复习，新的回测窗口从最近接触重新计算；不为了保留“一周”标签隐藏这次接触。
12. 建议由可复现规则产生，并附依据和实际目标词：最近独立首答失败优先建议独立提取；只有辅助成功的词建议尝试无提示；符合窗口的词提供延迟回测。各条件按此顺序处理，同词去重，每次最多三项建议，每项最多三个词。
13. 无客观样本时建议积累少量独立练习，不把暂无数据解释为能力不足。未到期词的专项练习需由用户明确启动，建议本身不改变到期状态。
14. 建议入口把实际词集合与题型绑定到练习上下文。进入后目标已删除或不再适用时解释变化，不悄悄换成其他词；没有有效词则显示空态。
15. 建议忽略用户输入速度作为能力证据；F5 可以用耗时估算计划，但不会因打字慢降低回忆状态。阅读选择错误只驱动对应阅读建议，不冒充单词独立提取失败。

### 6. F5：按可用时间形成每日词卡计划

1. 首页保留一键开始，默认使用 8 分钟；用户可以选择约 3/8/15 分钟。这里的预算覆盖每日词卡主队列及可选巩固，课程、故事、场景为另行启动的练习，不暗中塞入预算。
2. 开始前显示预计范围、本轮复习张数、新词数、可能的巩固题数、剩余到期量及依据。时间是估计，不是完成门槛或强制倒计时。
3. 候选沿用真实到期词优先、组内错词/困难词优先的规则。先按预算选到期词；仍有未纳入的到期词时，本轮不加入新词。到期词已全部纳入且预算有余时，才加入允许的新词。
4. 每轮最多二十张到期复习卡，巩固最多三题。当天新词总量不超过现有自适应建议：按该卡首次真实排期发生于今天的不同卡片扣减余量，迁移基线卡不冒充新词。继续第二轮不会重新得到完整日配额。
5. 默认估算为复习卡 20 秒、新词卡 40 秒、每道巩固 20 秒，加每轮固定操作开销 15 秒；按预算预留最多三题巩固的估计时间，剩余预算挑选主队列。若仍不足一张且有有效候选，允许一张并提示可能超时。
6. 个人同类样本至少五条后，以最近三十条有效样本的中位主动操作时长替代对应默认值；单条供估算的时长限定为 2–180 秒。估算样本不足时继续使用默认值并说明。
7. 耗时仅用于负担估计。后台标签页时间、保存请求等待时间和超过三十秒的连续无操作间隔不进入主动时长；无法可靠记录的样本不用于校准，不影响答案保存。
8. 预览可以随新数据重算；点击开始后冻结本轮卡序和总数。完成进度仍来自已保存的本轮事件与现有轮次索引，实际变慢不自动删卡、缩小目标或宣称完成。
9. 用户可在当前提交确认后选择“先到这里”，查看本段已保存结果。未作答题保留为未完成，既不新增跳过事件，也不算完成；同一浏览器可继续原轮次。
10. 保存中与保存未确认时先完成既有确认/放弃流程。预算耗尽不会自动跳题、取消请求或生成失败评分。刷新、退出与返回继续遵循既有待确认提交恢复规则。
11. 距最近活跃学习日中断至少三个学习日且存在到期词时，首页提供明确的恢复模式。默认约三分钟、最多五张到期词、本轮零新词；用户可另行选择常规计划。用户没有作答时，仅打开首页不结束中断状态。
12. 恢复模式结束后显示本段已完成及剩余到期量，不要求一次清空积压，也不重置原来的 FSRS 状态。
13. 预算选择和当前每日轮次仍属于浏览器偏好/状态；本次不承诺换设备续接同一每日队列。已保存作答和估算所需数据库记录随完整备份保留。

### 7. F6：有边界的文字场景练习

1. 首版提供买饮品、自我介绍、问路三种场景，每个场景固定三个用户应答轮次。首版输入为文字，可使用现有 TTS 听取角色话语；录音、语音识别和发音评分不属于本次交付。
2. 场景开始前显示中文任务、目标词汇的准备状态及约三轮的规模，不直接展开英文标准应答。用户按需查看标准应答时记录接触和相应轮次的辅助状态；用户可以先练或继续挑战，不能将刚展示过的表达计作延迟保持。
3. 每个场景有随应用分发并经过人工核对的任务规则、可接受表达/槽位、目标词映射和版本。目标应能用已有回忆依据的词与基础支撑表达完成，额外词汇需明确提示并允许先学。
4. AI 使用规则认可的场景、词汇和最近一轮结果生成角色回应及简短反馈。回应不能改变任务、标准答案、轮次上限或客观判定规则；超出允许词汇、泄露当前标准应答或缺少明确上下文的回应不能直接展示，使用核对过的模板继续。
5. 判定分为规则认可、规则明确不满足和无法可靠判定。未收录的合理表达或歧义答案显示未判定；模型说对/错均不能覆盖这个边界。空答案提示继续输入，只有用户明确跳过才记跳过。
6. 每轮最多提供一个关键纠正。用户可以请求提示或标准表达，也可用修改后答案继续；同一轮只保留一个计入首答表现的首次处理结果，后续是带来源的练习记录。
7. 当标准表达、包含待测答案的角色话语或其他提示已呈现时，该轮按辅助记录。界面不能通过关闭气泡或刷新清除帮助状态。
8. 三轮均处理后可显示“本次流程完成”；只有三个任务首答均规则认可且未使用提示时才显示“本场景独立通过”。存在跳过、未判定或辅助时分别列明，不能给出独立通过。
9. 语境应用证据只发给本次实际独立通过且与已存教学例句不同的任务情境及其显式覆盖目标。同一例句照抄不作为新情境证据；未满足此条件时可以记录练习完成，但标明迁移能力尚未验证。
10. 场景答案、提示、规则结果及关联修订作为任务证据持久化，不拆成多次单词 FSRS 评分；模型推断的能力不写入记忆排期。场景任务次数单列，不混入既有词卡完成量、独立提取正确率或按作答事件定义的连续学习日。需要补练词汇时提供独立练习入口，由用户启动后按输入题规则处理。
11. 保存答案、接受该轮结果并推进轮次是可确认的事务。AI 反馈在答案提交之后生成，失败时仍可查看已存结果、用模板继续或明确退出。
12. 场景轮次及已保存对话支持重新打开继续；已完成场景可查看历史或新开一轮。重复点击、刷新和网络重试不能重复加轮次、证据或练习成绩。

| 买饮品 | 请求一种饮品；表达数量；完成礼貌确认 | 如请求 water、表达 one、表示感谢。请求须有可识别的请求句型与目标饮品槽位，不能只凭答案包含 water 即判完成。 |
| 自我介绍 | 说明姓名；说明来自哪里；表达一种喜好 | 如 My name is …、I am from …、I like …。姓名和地点作为任务槽位，不把专名拼写评价为词汇记忆；缺少有效槽位时不得认可。 |
| 问路 | 礼貌询问指定地点；询问/确认一个方向；完成确认与感谢 | 使用明确给定的虚构地点和方向上下文，如 station 与 left。角色回复必须与这个上下文一致；存在歧义时不作事实或语言能力断言。 |

### 8. 接口与持久化契约

以下为本规格提出的公开行为契约，实施时不能通过仅调整界面来省略服务端约束：

| 公开操作 | 契约 |
| --- | --- |
| 词卡详情、列表与统计读取 | 在既有数据旁增加证据摘要、来源、日期、样本数和当前适用性。原有毕业兼容字段继续表示句子练习解锁，不重写已保存事件响应。 |
| 课程列表与详情读取 | 分别返回生成进度、浏览状态、短测结果和延迟回测结果；读取不新增作答。 |
| 生成课程/故事 | 完整校验后才写入；请求使用稳定操作标识，重复确认返回同一成功内容，同标识不同请求冲突。外部请求期间不持有数据库写锁。 |
| 创建练习上下文 | 接收用途与已有内容/目标身份；由服务端选题和冻结修订，返回轮次、有限题目及显示信息。无候选返回可解释空态，不能伪造题目。 |
| 获取、继续练习 | 返回已保存结果及实际未处理题目。草稿答案若只在浏览器保存，应明确其边界；已保存答案和提示状态以服务端为准。 |
| 请求提示/记录答案接触 | 以稳定标识记录提示与接触时间，在响应中提供确认。请求失败后 UI 不把本题提升为独立作答。 |
| 提交词汇/识别答案 | 通过现有统一学习提交能力处理，并原子关联题目结果。保留正确、辅助、跳过、是否排期与已保存标识；不增加第二次总成绩评分。 |
| 提交场景答案 | 服务端按冻结规则处理并保存任务结果，不调用客户端提供的评分，也不写单词 FSRS。 |
| 课程浏览完成/暂停等显式操作 | 保存其实际流程含义，不生成客观答对、每日完成或未知题的虚假跳过。 |
| 每日预览 | 返回预算、估算依据、有限卡序、配额与剩余量；不新增作答或更改排期。无预算参数保留默认入口。 |
| 建议与指标读取 | 只读并可追溯到已保存记录；同时返回样本量、不完整原因和可执行练习目标。 |

稳定的 URL 命名可沿用现有路由风格；本规格约束以上外部行为、参数含义和返回事实。输入检查与失败规则如下：

- 无效预算、用途、题目上下文或字段组合返回 422；不存在的内容/题目返回 404。
- 内容修订变化、题目失效、同一提交标识携带不同内容返回 409，并提供重新读取入口。未保存的旧提交不能静默改答案或换身份重放。
- 沿用题目上下文默认二十四小时有效的规则。服务重启后无法验证的未提交上下文要求重新加载；已保存提交仍可幂等确认。
- AI 未配置返回可识别的 503；上游失败或内容校验耗尽返回可识别的失败说明。场景可退回核对模板，词卡学习与现有内容仍可运行。
- 数据库提交失败返回未保存状态；保留当前答案和同一提交标识。响应丢失时允许确认原提交，不提前推进。
- 前端按当前轮次、题目、内容修订核对异步响应。旧请求晚到、换页和恢复数据后，不能替换当前内容或重复推进。
- 题目被删除后清楚显示不可继续，允许退出并查看已保存结果；不补入新的题目冒充原轮次，不将缺题算作通过。
- 无法保存浏览器 pending 时明确显示恢复能力有限；不承诺刷新一定找回未发送/未确认的草稿。

### 9. 数据升级、备份与领域决策

1. 新增内容修订、接触记录、练习上下文/题目关联、课程流程记录、场景任务结果及耗时估算所需记录。派生的证据状态和建议可以重算，不能成为独立于真实记录的第二份成绩。
2. 迁移采用向前升级并生成可恢复的升级前副本；保留卡片身份、FSRS 状态、学习事件、迁移基线、原课程与故事。升级不触发 AI 生成，不补造旧浏览或测试结果。
3. 为包含新增集合的完整快照引入 V3 备份，登记全部新业务集合和引用。完整备份覆盖已保存的新学习内容，仍排除密钥、环境配置、语音缓存和浏览器偏好/每日队列状态。
4. 保留 V1 部分恢复和 V2 完整备份的读取支持。V2 恢复前明确预览“该版本没有新增学习记录，替换后这些记录将为空”；执行前保存 V3 安全副本，确认后原子替换。缺少新证据显示未知，不从旧计数推造。
5. V1 部分恢复沿用其合并边界；被实际修改的内容按修订规则重新判断证据，不清空无关新记录。新版本不能将 V3 文件冒充 V2，旧版本对未知版本明确拒绝。
6. V3 恢复校验所有新引用、修订、规则版本、操作/提交唯一性和保存结果。相关 ID 重新映射，已保存提交确认保持业务等价；签名密钥不随备份恢复，未提交旧题应重新获取。
7. 恢复沿用预览修订冲突、全量替换确认、安全副本和失败回滚机制。恢复成功后清除浏览器已失效的轮次缓存，重新读取服务端已保存练习；恢复前启动的后台生成结果不得写入恢复后内容。
8. 物理删除卡片/内容后，关联证据不得用于当前统计或推荐；已存流程可以展示明确的不可用题目快照，但不能保留可被重用的悬空活引用。全量备份必须能独立解释和验证这种状态。
9. **ADR-0001：** 当前状态与只追加事件、幂等、提示/识别不排期、先保存后推进继续适用。毕业字段仍为兼容解锁口径；本规格新增客观能力维度，不把它改写成原字段的新含义。
10. **ADR-0002 的拟议扩展：** 增加延迟回测、内容接触和时间预算规则；时间预算路径对未纳入全部到期词时的新词安排更严格，并按全日已学新词扣减配额。它改变了当前只按固定轮次挑词的编排规则，实施时须明确更新相应决策。既有日目标与新词建议分离、保存后推进、事件归属学习日继续适用。
11. **ADR-0003 的拟议扩展：** 当前只定义 V2，无法容纳所有新集合。本规格要求新增 V3 兼容决策，不直接变更旧 V2 文件含义；恢复安全边界继续适用。
12. 本规格未直接修改现有 ADR。实施须将以上扩展记录为新的领域决策或现有决策的明确增补，不能悄悄覆盖已采纳语义。

## 测试决策 / Testing Decisions

### 1. 好测试的标准与既有实践

- 只验证外部可观察行为：用户看到什么、操作是否成功保存、结果是否可解释、公开读取及备份能否核对。不要用内部函数调用次数、组件私有状态或 ORM 写法替代行为断言。
- 主验收复用现有 Playwright 应用夹具、双视口、迁移数据库、可控时钟、提交故障和网络注入设施。正常学习必须实际经过后端、事务、调度与数据库。
- 已有每日主队列、有限巩固、输入题独立/辅助区分、分类统计、签名识别题、刷新确认及 V2 恢复用例可作为先例。扩展这些用户路径，不重复搭建第二套测试服务器。
- 公开 HTTP 集成先例是经真实迁移建立的隔离应用环境；迁移与完整恢复的非法引用、事务故障和并发重放继续通过该边界补充。
- 时钟分别验证时间差和学习日：跨午夜但不足二十四小时不能成为隔日保持；七天窗口按 UTC 实际时长，学习日去重用事件写入时固定的时区。
- 失效/边界值包括 24 小时、72 小时、七天、十四天、三十天，以及每个边界前后的可控时刻。不得依靠任意等待或真实网络偶然响应。
- 生成替身必须包括格式正确但违反难度、目标词遗漏、中英缺失、错误上下文和晚到响应等情况；仅测合法 JSON 不能证明内容校验成立。
- 本规格只修改文档时做结构、范围覆盖、交叉引用与矛盾检查；实施后才运行下面的软件验收并记录实际结果。本规格不是测试通过报告。

### 4. 内容质量与学习效果观察

- 三类场景的分发规则、可接受表达、模板和支撑词表必须先由具备英语教学判断能力的人核对，登记版本；自动化不能替代这一内容验收。
- 新故事和课程的真实生成样本至少覆盖词汇不足、少量已知词和较充分已知词三种准备状态，每种状态抽三例；人工检查语义、自然程度、翻译和题目是否唯一可判。发现错误应修正规则/材料后重验受影响样本，不用总体均分掩盖错误题。
- 可先由本人和 3–5 位用户连续试用两周，观察实际用时、提示次数、中途退出原因、延迟回忆及不同任务结果。试用仅在参与者同意后进行，本任务不自动招募或联系他人。
- 小样本用于发现流程与内容问题，不宣称统计意义的教学效果提升。验收条件不要求事先承诺某个留存或学习提升百分比。

## 明确不做 / Out of Scope

1. 本次不重写技术栈，不引入微服务、向量数据库、复杂知识追踪模型或另一套 FSRS。
2. 不做用户账户、多人后台、云同步、付费订阅、增长投放、排行榜或社交系统。
3. 不做开放式无限聊天、任意场景市场、长对话记忆或让模型自行决定课程进度。
4. F6 首版不做录音、实时语音对话、ASR、音素评分或口音评价；文字场景与既有 TTS 完成六项中的场景交付范围。
5. 不提供官方 CEFR 测评、考试成绩、英语综合水平认证或“学过二十课即达到某等级”的承诺。
6. 不把复习次数、模型赞扬、反应速度、自评、带提示答对或识别题正确率换算为长期掌握概率。
7. 不为了测量一周保持而强制用户延后正常复习，不伪造未发生的日期、作答、接触或应用证据。
8. 不监控应用外的学习，不承诺完全识别用户看过的所有内容，也不把记录缺失解释为未接触。
9. 不提供离线自动提交重放，不承诺跨设备续接浏览器每日轮次或恢复未保存草稿。
10. 不要求学习者清空全部积压才算有进展，不把时间预算作为强制倒计时或新的每日硬门槛。
11. 不借本规格进行全面视觉改版；只调整解释状态、执行练习与恢复操作所需的界面。
12. 本次文档交付包含已确认 tickets、实施计划和 GitHub Issues 发布；不实施产品、不修改已采纳 ADR、不部署。新增领域决策由各实施票按计划同步。

## 假设 / Assumptions

| 编号 | 本规格采用的默认值或判断 | 改动影响 |
| --- | --- | --- |
| A01 | 用户为个人及少量本地实例使用者，沿用既有学习时区 | 不引入身份、云同步或多租户规则 |
| A02 | 两个不同学习日、至少相隔 24 小时的首答独立正确作为当前回忆证据 | 调整后需更新状态判定及边界测试 |
| A03 | 一周回测有效正确提供长间隔保持证据；证据 30 天后显示待复测 | 规则需有版本，不能改写原事件 |
| A04 | 隔日窗口为 [24,72) 小时，一周窗口为 [7,14) 天；独立样本不足十个提示较少 | 影响统计口径、候选和展示 |
| A05 | 课后短测三题、全部独立正确通过，少词按实数说明 | 只证明实际被测内容，不推断整课口语能力 |
| A06 | 故事默认 40–70 词/句长最多 12；简化 20–40 词/句长最多 8；未覆盖词形最多两个 | 需验证对实际零基础用户是否可理解 |
| A07 | 生成内容校验失败最多自动修正一次；仍失败保留原内容 | 影响等待成本与失败体验 |
| A08 | 每日预算 3/8/15 分钟，默认 8；估算 20/40/20 秒与 15 秒开销 | 均为初始负担估计，个人样本足够后校准 |
| A09 | 个人估算至少五个同类样本，使用最近三十条有效样本中位数 | 耗时不进入能力判断 |
| A10 | 中断至少三个学习日且有到期词时推荐恢复模式，最多五张、零新词 | 需观察能否帮助恢复且不加重后续负担 |
| A11 | 首版三类场景、每次三个用户应答轮次，采用核对规则与可控 AI 回应 | 自由表达覆盖有限，无法判断时明确未判定 |
| A12 | 新的完整备份采用 V3，继续支持 V2/V1 读取 | 引入版本适配、升级与恢复验收，不能在 V2 内隐式扩格式 |
| A13 | 当前毕业作为拓展解锁兼容保留，能力证据独立计算 | 减少修改既有排期和句子卡生成契约的范围 |

以上均有可执行默认行为，不等待新一轮访谈才能实施；若后续调整，应同步规格、规则版本与验收条件。

## 未决问题 / Open Questions

1. **教学阈值是否合适？** 两次跨日正确、30 天证据提示和回测窗口是产品初值，后续根据个人表现与教学评估调整；首版按假设执行，不阻断实现。
2. **基础支撑词与场景表达如何扩充？** 首版提供有版本、人工核对的最小集合。扩充采用内容评审，不把模型生成直接加入权威答案；具体负责人在内容验收前确定。
3. **文字任务是否值得扩展为语音？** 先观察任务完成与求助情况；语音另立规格，不阻断六项首版完成。
4. **延迟统计的代表性有多强？** 词样本和用户选择可能有偏差；首版报告实际覆盖、首测处理结果和间隔，不宣称代表全部词汇。随机抽样或对照实验是后续评估设计。
5. **接口与表命名已有实施决策。** 见实施计划的共享接口契约及各票文件职责；后续若因源码漂移调整名称，同步所有消费者并保持操作含义、事务和兼容边界，不改变验收。
6. **发布授权已解决。** 用户已明确授权将已确认 tickets 和实施计划上传 GitHub Issues，直接标记 `ready-for-agent`；实际编号与链接见 ticket 发布记录。

## 验收条件 / Acceptance Criteria

| 编号 | 可独立判断的通过条件 |
| --- | --- |
| AC01 | 三次独立失败不会在任何新版入口显示已掌握或 100% 掌握；复习次数可以如实显示。 |
| AC02 | 既有毕业/句子卡能力保留为明确的练习解锁，不能被显示成长期记忆或综合英语能力。 |
| AC03 | 独立、辅助、识别、自评和跳过始终分列，证据与排期按各自规则解释，模型不能覆盖。 |
| AC04 | 回忆证据满足两个不同学习日且至少相隔 24 小时的首答独立正确；同日重试与仅跨午夜不满足。 |
| AC05 | 每个能力状态可读出证据类别、数量、日期、修订和适用性；样本不足或缺失明确说明。 |
| AC06 | 新失败使对应当前证据待巩固，超过 30 天标待复测；历史成功仍可查看，不制造失败事件。 |
| AC07 | 实质修改内容后旧证据成为历史，升级前依据不足的数据不被自动补齐为当前掌握。 |
| AC08 | 课程已生成、已浏览、短测通过和延迟结果分别展示；生成二十课不能使新版页面显示已学完。 |
| AC09 | 每课有明确目标，浏览完成由显式操作记录；打开课程不新增一次作答或客观成功。 |
| AC10 | 短测有限、题目不泄露答案；全部实际题目首答独立正确才通过，辅助或错误转待巩固。 |
| AC11 | 用户能选择稍后检查并继续下一课，原课保留待测；各进度计数来自对应事实。 |
| AC12 | 少词、空题、缺失卡、重试、刷新路径能解释当前状态，不能用重复练习覆盖原首次结果。 |
| AC13 | 课程内容与词卡原子生成，非法内容/写入失败不新增半课、重复词或错误推进生成级别。 |
| AC14 | 故事目标与用户词汇依据相关，长度、句长、未覆盖词形、目标出现和中英配对由服务端校验。 |
| AC15 | 词汇不足提供可用入门材料或明确空态，基础支撑词与个人已知词分别解释，新词不自动入库。 |
| AC16 | 更简单操作生成有独立身份的短版本并保留原版，旧结果不归给新版。 |
| AC17 | 读后最多两题，理解识别与词汇提取分开；回看原文/提示后不显示独立提取。 |
| AC18 | 故事阅读与即时检查不算延迟保持；旧故事仍可读，缺题不伪造通过。 |
| AC19 | 两次生成仍不合格或外部失败时保留已有内容，提供可解释失败与继续入口。 |
| AC20 | 延迟回测使用已存接触依据和实际 UTC 间隔，严格按两个窗口及其他间隔分类。 |
| AC21 | 提示、跳过、新接触和间隔记录不完整分别处理；其他标签页接触能够取消原窗口资格。 |
| AC22 | 每词每学习日每窗口首测不被重试替换；显示独立成功/样本数、辅助、跳过及覆盖量。 |
| AC23 | 旧接触数据不完整时只能作普通练习并建立新依据，无样本显示暂无数据。 |
| AC24 | 建议说明具体依据、词和匹配练习入口，同词去重并有数量上限；不自动改变词卡到期。 |
| AC25 | 指定词练习中目标变化、删除和空池均有明确提示，不暗中换词或伪造完成。 |
| AC26 | 三种时间预算均能预览、开始有限计划；到期词优先，仍有到期词未纳入时不加新词。 |
| AC27 | 每轮复习至多二十张、巩固至多三题，当日新词余量按真实首排期扣减，继续多轮不重领配额。 |
| AC28 | 估算说明默认/个人依据，足够样本后校准；闲置、后台及保存等待不影响能力判断。 |
| AC29 | 开始后目标固定；暂停、超时和刷新不缩目标或产生未作答题的虚假跳过，同浏览器可以继续。 |
| AC30 | 中断恢复模式有限、零新词，原 FSRS 保留，结束显示剩余到期量且可返回常规学习。 |
| AC31 | 三类文字场景各有任务、准备状态和三轮上限；目标与用户学习依据有关。 |
| AC32 | 流程完成与独立通过分列；未知表达、提示、跳过不被计成独立通过，模型不能改变判定。 |
| AC33 | 应用证据有场景、目标、规则与内容修订依据；照抄已教例句不被当作新情境验证，不推断未测能力。 |
| AC34 | 场景单轮只纠正一个关键问题；AI/语音失败可用模板或查看已存结果，不能撤销作答或额外评分 FSRS。 |
| AC35 | 六项中所有保存失败/响应丢失路径保留原题、答案及稳定提交身份，确认前不推进或显示已完成。 |
| AC36 | 题目失效、内容冲突、删除、晚到响应及恢复后的旧请求均有可恢复处理，旧结果不能污染当前上下文。 |
| AC37 | 同身份同内容重复确认只生效一次，同身份不同内容明确冲突；结果及关联写入同一事务。 |
| AC38 | 空库和代表性旧库通过真实迁移升级，学习数据保留，不生成虚假旧成绩或自动 AI 内容。 |
| AC39 | V3 完整导出恢复后，新旧学习记录、引用、规则与修订、已保存轮次结果及提交回放保持业务等价。 |
| AC40 | V1/V2 恢复有明确缺失范围预览；V2 替换会清空的新记录提前告知，并有可恢复 V3 安全副本。 |
| AC41 | 非法引用、不兼容版本、预览后变化和执行故障不能造成部分替换；取消和失败保留目标数据。 |
| AC42 | 恢复不带入密钥和签名密钥，旧未提交题重取；恢复前后台响应不能写入恢复后实体。 |

## 补充说明 / Further Notes

### 1. 仓库事实与本规格的关系

- 现有系统已区分独立输入、辅助输入、识别和自评，也已实现保存确认、重试去重、有限巩固和真实事件统计。本规格扩展其用途，不把已有能力重新写成从零建设。
- 当前课程进度以生成级别和数量表示；课程“记住了”是自评。新增课程学习状态不能由旧生成数量推造。
- 当前故事的默认选词是没有复习记录的新词，和“用已掌握词复习”的理想体验不同；本规格明确改变这一选择规则。
- 当前每日队列以单词卡为主，句子拓展有独立入口。本规格没有把所有句子卡强制塞入每日队列。
- 当前完整备份为 V2，且题目枚举和关联有严格校验。新增业务记录必须显式纳入新版本，不依赖未登记的字段自然进入备份。
- 现有最高验收环境已经支持隔离迁移库、时钟、外部提供方替身和提交故障；本规格复用这些准备能力。

### 2. 对齐领域决策

遵循 ADR-0001《当前记忆状态与只追加学习事件》、ADR-0002《学习日与活动统计》、ADR-0003《版本化完整备份与恢复契约》。本规格提出的编排与 V3 扩展已在实现决策中显式指出，不将提案当作现有已采纳规则。

不新增平行领域上下文或另一套术语文档。当前根目录无领域词汇表时，使用上述现有术语，并在后续已授权的领域文档维护中统一记录稳定的新术语。

### 3. 发布与完成定义

- 本文件可作为之后 tracker 发布的完整正文来源，不需要依赖聊天记录解释目标、范围、行为或异常路径。
- 外部发布必须获得明确授权，使用项目配置的 GitHub Issues，通过正文文件发布并标记 `ready-for-agent`。本地文档完成不等于发布，也不意味着已开始产品实现。
- 实施完成须满足全部 AC01–AC43、六项主路径与必要异常分支，并记录实际验收证据。分阶段完成可以单独报告，但不代替整份规格完成。
