# 版本回退兼容边界（EC-16）

验证基线为真实 Git 提交 `5868cd1629bc3c36f2bfd5a1009ae048481c94f8`。`e2e/support/legacy-app.mjs` 用 `git archive` 解包到独立临时目录，实际导入该版本的应用、路由与 ORM；不换成当前应用，不执行旧迁移。缺少该提交或旧应用启动失败是阻塞，命令非零退出。

演练使用 SQLite backup API 从迁移后的隔离实例复制数据库，不使用用户库，也不让旧进程连接原实例。旧版连接为 SQLite URI `mode=ro&uri=true`；外层 ASGI 兼容壳对 POST/PUT/PATCH/DELETE 等修改方法返回 503，提示“兼容模式只读；继续学习请使用当前后端”。这两层保护必须同时存在。

已验证的只读范围为词卡列表和已有中文译文的故事详情。对缺少译文的故事，旧 GET 会自动翻译并提交数据库；演练只替换外部翻译提供方，促使真实旧路由尝试写入。SQLite 拒绝写入，兼容壳把失败显式转换为只读 503，并记录 `READ_ONLY_LEGACY_SQLITE_WRITE_BLOCKED`。不能把这种读取失败描述为旧版完整可用。其他旧功能、后台写入或未测的读取路径不在兼容承诺内；SQLite 只读连接仍负责阻止写入。

`e2e/ec-16-compat.spec.mjs` 在两个视口的测试项目中，使用当前公开 V2 导出比较演练前后全部业务内容（只排除 `exported_at`）。已有新事件保持不变；关闭旧实例后，当前后端能再保存一个新事件。原隔离实例也保持不变。另一测试验证隐式 GET 写入被阻止且快照完整。

原版后端不追加学习事件，恢复旧版写入会使当前状态与历史脱节；因此不能安全地让旧后端继续学习、部分恢复或全量恢复。EC-15 的迁移降级只撤当前状态唯一约束，保留事件、基线和身份高水位；它不会赋予原版后端新的写入语义。代码回退和数据库快照恢复是不同操作，不能用旧快照覆盖升级后新增的进度。

遇到版本问题时：

1. 停止有风险的写入和后台任务，保留当前数据库及 SQLite backup 副本，并在当前后端可用时下载 V2 完整备份。
2. 优先只回退界面，保留支持事件、幂等和恢复 ID 契约的当前后端；若必须使用旧版，仅在只读副本上核对上述已验证读取范围。本测试壳用于隔离演练，不是通用生产代理。
3. 前向恢复使用当前版本代码与依赖，停止旧进程后，针对保留的新数据库执行 `python -m alembic upgrade head`，再启动当前后端。不要执行旧迁移，也不要替换为升级前旧库。
4. 核对词卡、排期、事件与关联，再保存一次新评分，检查事件增加。若需要从备份恢复，重新预览影响范围并明确确认；不得反复导入旧文件覆盖后来进度。

运行 `npm --prefix frontend run test:e2e -- --ticket EC-16` 可重做隔离演练。整体交付状态及最终未过滤命令见 [发行证据](release-evidence.md)，单票通过不代表父规格所有验收完成。
